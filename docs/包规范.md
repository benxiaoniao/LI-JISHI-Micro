# 包规范（H4 最小切分：源码包 + 单 `.jmb`）

> 状态：🟡 最小可用切分已落地。范围只到「本地路径依赖的源码包，在源码层合并，产出一个 `.jmb`」。
> 不改 JMB 格式、不改 VM、目标侧新增 0 B。二进制包、`.jmb` 内嵌/归档、多 `.jmb` 链接仍留到 H4b（依赖 JM10）。

## 1. 已拍板的 7 项

| 决定 | 结论 |
|------|------|
| 分发形态 | 只发**源码包**（`砾包.toml` + `.jsh`），不发二进制包 |
| 合并方式 | **源码级合并**：多包 AST 进同一个 Program，编出一个 `.jmb` |
| 版本策略 | **单版本**：一个包名只允许一个版本；菱形依赖只装一份 |
| 名字表 | 保持 JMB v4 的 `u8` / 255 上限，超限报 **E124** 并列出占用最多的包 |
| 版本约束 | 只支持**精确**（`1.2.3`）、**`^`**（`^1.2.3`）、**`*`** |
| 锁文件 | **必须**：`micc install` 生成 `.砾/锁.toml`，离线按锁还原 |
| native ABI | 包声明的 `原生ABI` 与编译器不一致就**拒绝**（E129），不做兼容降级 |

## 2. `砾包.toml`

只解析一个 TOML 子集：`[表]`、`键 = 值`、字符串/整数/字符串数组/内联表，`#` 注释；支持 UTF-8 BOM；不支持 `[[数组表]]`。

```toml
[包]
名字 = "应用"              # 必填，包名唯一
版本 = "1.0.0"             # 必填，主.次.修订
入口 = "主.jsh"            # 可选，默认 主.jsh
原生 = ["引脚"]            # 可选，本包用到的 native 模块
原生ABI = 1                # 可选，默认当前编译器的 ABI 版本
字节码上限 = 65535         # 可选，默认 65535（且不超过 65535）
堆预算 = 6144              # 可选，默认 6144（STM32F103 的 JM_HEAP_SIZE）

[依赖]
工具 = { 路径 = "../工具", 版本 = "^0.1.0" }   # 版本可省略，等于 *

[导出]
名字 = ["加一", "问候"]    # 可选；出现这个表就表示「只导出列出的名字」
```

- `[导出]` 只能写一行 `名字 = [...]`；列出的名字必须在包顶层存在，否则 E125。
- 不写 `[导出]` 表示顶层名字全部可被跨包引用。
- `[依赖]` 的键必须与依赖包 `[包] 名字` 一致；同名依赖重复声明报 E125。

## 3. 版本与约束

- 版本是 `主.次.修订` 三段十进制。
- `1.2.3`：精确匹配。
- `^1.2.3`：主版本相同且 `>= 1.2.3`。
- `^0.2.3`：主版本为 0 时按次版本锁，要求 `0.2.x` 且 `>= 0.2.3`。
- `*`：任意版本。
- 其他写法（`~`、范围、通配段）在解析清单时直接报 E125。

## 4. 依赖解析

`micc pack` 与 `micc install` 共用一套在线解析：

1. 从根包目录读 `砾包.toml`，按依赖名字典序遍历；
2. 每个依赖先规范化目录（判环），再读它的 `砾包.toml`；
3. **按包名去重**：同名、同目录只解析一次（菱形依赖天然只装一份）；
4. 同名但来自不同目录 → E126，报两个目录；
5. 已解析过的包版本不满足新约束 → E126，报**来源链**（`应用 → 右 → 基础`）；
6. 目录成环 → E126，报 `依赖成环：A → B → A`；
7. 输出拓扑序（被依赖的包在前），后续合并按这个顺序拼接。

## 5. 源码级合并与可见性

- 依赖包顶层**只允许声明**：`导入`、`令`、`函数`、`类`。出现 `打印(...)`、`如果`、`遍历` 等可执行语句 → **E127**。
- 依赖包的顶层全局名字统一改写为 `包名::名字`，包内引用同步改写，因此不同包的同名函数互不干扰。
- 根包引用依赖包写成 `包名.名字` / `包名.函数(...)`；改写时按被引用包的 `[导出]` 做可见性检查，未导出 → **E128**。
- 跨包引用类（`包名.类名`、跨包 `新建`）本切片不支持 → E128；类只在包内使用。
- 合并后整个程序共用一张名字表、常量表、类表、代码表。

## 6. 名字表与预算

- 名字表仍是 `u8` 下标、最多 255 项。超限报 **E124**，提示按 `包名::` 前缀统计，列出占用最多的前 3 个包（单文件编译算 `<入口包>`）。
- 堆预算：静态估算堆下界（列表 `12 + 4n`、字典 `12 + 8n`、新建实例 `16 + 4×字段数`），只允许用到 `堆预算` 的 80%；超了报 **E130**。这是下界，不含循环里反复分配的量。
- `.jmb` 体积：超过 `min(字节码上限, 65535)` 报 **E130**。
- native 需求：各包 `原生` 取并集；合并后的源码里每个 `导入 模块` 都必须在并集里，否则 E129。每个包的 `原生ABI` 都必须等于编译器的 ABI（当前 v1），否则 E129。

## 7. 锁文件与离线

`micc install`：

1. 在线解析整棵依赖树；
2. 把每个包复制到根包的 `.砾/包/<名字>-<版本>/`；
3. 对复制后的目录算 FNV-1a 64 内容哈希（跳过 `.砾`、`.git`、`build`、`target`、`node_modules`）；
4. 写 `.砾/锁.toml`。

```toml
# 本文件由 micc install 生成，不要手改
锁版本 = 1

[包]
工具 = { 版本 = "0.1.0", 来源 = "path:../工具", 校验 = "fnv1a64:06505cae7fb7fabb" }
```

`micc pack --离线` / `micc install --离线`：

- 只读 `.砾/锁.toml` 与 `.砾/包`，**不看** `[依赖] 路径`，不碰网络；
- 缺锁、锁里没有、缓存目录不存在 → E126（「离线模式缺包」）；
- 缓存里的清单名字/版本与锁不一致，或内容哈希不一致 → E126（「离线模式校验失败」）；
- 锁里多出来的包也要能在缓存里找到（同一把锁还原同一棵树）。

`.砾/包/` 是缓存，不入库；`.砾/锁.toml` 应当入库。

## 8. 命令

```
micc pack [--目录 <包目录>] [-o 输出.jmb] [--离线]
micc install [--目录 <包目录>] [--离线]
```

- `pack` 默认输出 `<包目录>/<包名>.jmb`；`--目录` 默认当前目录。
- `pack` 成功时打印依赖列表、名字/常量/函数/类用量、字节码大小、堆下界、原生并集、输出路径。
- `install` 成功时打印每个包的版本与来源；`--离线` 只做校验并打印锁条目。

## 9. 错误码

| 码 | 含义 |
|----|------|
| E124 | 打包后名字表超过 255（提示列出占用最多的包） |
| E125 | `砾包.toml` / 锁文件格式错误（字段、版本语法、缺失项、导出名不存在） |
| E126 | 依赖解析失败：目录不存在、成环、同名不同目录、版本冲突、离线缺包/校验失败 |
| E127 | 依赖包顶层出现可执行语句 |
| E128 | 引用未导出的名字，或跨包把类当值用 |
| E129 | native 冲突：ABI 不一致、模块不存在、源码导入未声明的模块 |
| E130 | 静态预算超限：堆下界超过预算 80%，或 `.jmb` 超过字节码上限 |

## 10. 仍未覆盖（H4b 及以后）

- **二进制包**：只发源码，`砾包.toml` 里没有 `预编译`/`产物` 字段。
- **`.jmb` 内嵌/归档与多 `.jmb` 链接**：等 JM10 固化打包规则后再定，避免规则一变返工。
- **跨包 `新建` 类**：需要语法扩展（例如 `新建 包名.类名`），当前报 E128。
- **目标板字段**：`砾包.toml` 暂无 `目标板`，烧录目标仍由构建脚本决定。
- **索引与网络来源**：只有本地路径依赖；`micc search` / `micc publish` 属于 H5。
- **锁更新策略**：没有 `micc update`，也没有最小版本选择；锁只由 `install` 全量重写。
