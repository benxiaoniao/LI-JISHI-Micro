# 包规范（H4 源码包 + H4b 归档/二进制包 + H5 静态索引 + P2 发布与检索）

> 状态：🟡 H4 最小切分（本地路径依赖的源码包，源码级合并，产出一个 `.jmb`）已落地；
> **H4b（2026-11-09）：`.jmb` 归档、源码归档、二进制包字段、接口清单、`micc verify`、本地归档安装已落地**；
> H5 做了**静态索引**与 `micc install` 的索引解析；**P2（2026-11-09）补了 `micc publish` / `micc search`**——仍是文件级（目录式仓库 + `砾索引.toml`），没有服务器、上传与鉴权。
> 不改 JMB 格式、不改 VM、目标侧新增 0 B。多 `.jmb` 链接**明确不做**，理由见 §11。

## 1. 已拍板的 7 项

| 决定 | 结论 |
|------|------|
| 分发形态 | 只发**源码包**（`砾包.toml` + `.jsh`），不发二进制包 |
| 合并方式 | **源码级合并**：多包 AST 进同一个 Program，编出一个 `.jmb` |
| 版本策略 | **单版本**：一个包名只允许一个版本；菱形依赖只装一份 |
| 名字表 | 保持 JMB 的 `u8` / 255 上限，超限报 **E124** 并列出占用最多的包 |
| 版本约束 | 只支持**精确**（`1.2.3`）、**`^`**（`^1.2.3`）、**`*`** |
| 锁文件 | **必须**：`micc install` 生成 `.砾/锁.toml`，离线按锁还原 |
| native ABI | 包声明的 `原生ABI` 与编译器不一致就**拒绝**（E129），不做兼容降级 |

## 2. `砾包.toml`

只解析一个 TOML 子集：`[表]`、`键 = 值`、字符串/整数/字符串数组/内联表，`#` 注释；支持 UTF-8 BOM；不支持 `[[数组表]]`。

```toml
[包]
名字 = "应用"              # 必填，包名唯一
版本 = "1.0.0"             # 必填，主.次.修订
入口 = "主.jsh"            # 可选，默认 主.jsh
原生 = ["引脚"]            # 可选，本包用到的 native 模块
原生ABI = 2                # 可选，默认当前编译器的 ABI 版本
字节码上限 = 65535         # 可选，默认 65535（且不超过 65535）
堆预算 = 6144              # 可选，默认 6144（STM32F103 的 JM_HEAP_SIZE）
产物 = "工具.jmb"          # 可选；出现即「二进制包」：只发预编译产物，不带源码

[依赖]
工具 = { 路径 = "../工具", 版本 = "^0.1.0" }   # 本地路径依赖；版本可省略，等于 *
索引包 = { 版本 = "^1.0.0" }                    # 不写 路径 = 从静态索引解析（H5）

[导出]
名字 = ["加一", "问候"]          # 可选；出现这个表就表示「只导出列出的名字」
类型 = ["计数器", "状态"]        # 可选；跨包可见的类/枚举白名单
```

- `导入 文本/列表/字典` 是标准库模块，不需要写进 `[包] 原生`；未导入时函数名不存在（E112）。
- `[导出]` 只支持 `名字 = [...]` 与 `类型 = [...]`；列出的名字必须分别在包顶层存在，否则 E125。
- `[导出]` 是**可选白名单**：不写 `名字` 时所有公开名字可跨包；不写 `类型` 时所有公开类型可跨包。写了就按清单过滤。
- 顶层声明**默认公开**；在声明前写 `私有`（`私有 令/函数/类/枚举`）就只在包内可见。私有名字写进 `[导出]` 报 E144。
- `[依赖]` 的键必须与依赖包 `[包] 名字` 一致；同名依赖重复声明报 E125。
- `路径` 可省略：省略后该依赖从静态索引解析（见 §8）；`版本` 也可省略，等于 `*`。

## 3. 版本与约束

- 版本是 `主.次.修订` 三段十进制。
- `1.2.3`：精确匹配。
- `^1.2.3`：主版本相同且 `>= 1.2.3`。
- `^0.2.3`：主版本为 0 时按次版本锁，要求 `0.2.x` 且 `>= 0.2.3`。
- `*`：任意版本。
- 其他写法（`~`、范围、通配段）在解析清单时直接报 E125。

## 4. 依赖解析

`micc pack` 与 `micc install` 共用一套在线解析：

1. 从根包目录读 `砾包.toml`，按依赖名字典序遍历；
2. 每个依赖先规范化目录（判环），再读它的 `砾包.toml`；
3. **按包名去重**：同名、同目录只解析一次（菱形依赖天然只装一份）；
4. 同名但来自不同目录 → E126，报两个目录；
5. 已解析过的包版本不满足新约束 → E126，报**来源链**（`应用 → 右 → 基础`）；
6. 目录成环 → E126，报 `依赖成环：A → B → A`；
7. 输出拓扑序（被依赖的包在前），后续合并按这个顺序拼接；
8. 依赖写了 `路径` 就是本地路径依赖；不写 `路径` 就从静态索引解析（§8），按约束取满足条件的**最高版本**；
9. 在线 `pack` 遇到索引依赖时**只读锁与缓存**，不下载、不读索引；下载与选版只发生在 `micc install`。

## 5. 源码级合并与可见性

- 依赖包顶层**只允许声明**：`导入`、`令`、`函数`、`类`、`枚举`。出现 `打印(...)`、`如果`、`遍历` 等可执行语句 → **E127**。
- 依赖包的顶层全局名字统一改写为 `包名::名字`，包内引用同步改写，因此不同包的同名函数互不干扰。
- 根包引用依赖包写成 `包名.名字` / `包名.函数(...)`；改写时按被引用包的 `[导出] 名字` 与 `私有` 做可见性检查，未导出/私有 → **E128**。
- 顶层类/枚举默认公开：
  - 类：`新建 包名.类名(实参...)`，类型标注可写 `参数: 包名.类名`；
  - 枚举：取成员写 `包名.枚举名.成员`，`匹配` 模式同样写法；
  - 标了 `私有` 或不在 `[导出] 类型` 清单里 → **E128**；类名当值用（`令 c = 包名.类名`）也报 E128，提示改用 `新建`。
- `私有` 只能写在模块顶层；写在类体、函数体或表达式位置、重复写、私有名字写进 `[导出]` 都报 **E144**。
- 跨包**继承**仍不支持：`继承 父类` 的父类必须与子类在同一模块（E140）；跨包组合请用导出函数/组合字段。
- 合并后整个程序共用一张名字表、常量表、类表、代码表。

## 6. 名字表与预算

- 名字表仍是 `u8` 下标、最多 255 项。超限报 **E124**，提示按 `包名::` 前缀统计，列出占用最多的前 3 个包（单文件编译算 `<入口包>`）。
- 堆预算：静态估算堆下界（列表 `12 + 4n`、字典 `12 + 8n`、新建实例 `16 + 4×字段数`），只允许用到 `堆预算` 的 80%；超了报 **E130**。这是下界，不含循环里反复分配的量。
- `.jmb` 体积：超过 `min(字节码上限, 65535)` 报 **E130**。
- native 需求：各包 `原生` 取并集；合并后的源码里每个 `导入 模块` 都必须在并集里，否则 E129。每个包的 `原生ABI` 都必须等于编译器的 ABI（当前 v2），否则 E129；ABI v1 的旧包需要重新打包。

## 7. 锁文件与离线

`micc install`：

1. 解析整棵依赖树（路径依赖读目录，索引依赖按 §8 挑版本、取内容、校验哈希）；
2. 把每个包复制到根包的 `.砾/包/<名字>-<版本>/`；
3. 对复制后的目录算 FNV-1a 64 内容哈希（跳过 `.砾`、`.git`、`build`、`target`、`node_modules`）；
4. 写 `.砾/锁.toml`。

```toml
# 本文件由 micc install 生成，不要手改
锁版本 = 1

[包]
工具 = { 版本 = "0.1.0", 来源 = "path:../工具", 校验 = "fnv1a64:06505cae7fb7fabb" }
索引包 = { 版本 = "1.2.0", 来源 = "index:file:工件/索引包-1.2.0", 校验 = "fnv1a64:..." }
```

`micc pack --离线` / `micc install --离线`：

- 只读 `.砾/锁.toml` 与 `.砾/包`，**不看** `[依赖] 路径`，不碰网络；
- 缺锁、锁里没有、缓存目录不存在 → E126（「离线模式缺包」）；
- 缓存里的清单名字/版本与锁不一致，或内容哈希不一致 → E126（「离线模式校验失败」）；
- 锁里多出来的包也要能在缓存里找到（同一把锁还原同一棵树）。

`.砾/包/` 是缓存，不入库；`.砾/锁.toml` 应当入库。

## 8. 静态索引（H5 最小切分）

**边界先说清：本项目不跑服务器。** 这里只做**静态索引文件**——一个能放在 GitHub raw 或本地目录里的
`砾索引.toml`，由 `micc` 读取、按版本约束挑版本、取内容、按 H4 的哈希校验。
P2 起有 `micc publish` / `micc search`，但两者都只操作本地文件：没有上传接口、没有鉴权、没有账号，
索引与归档仍由使用者自己放到可访问的位置。

格式（复用 `砾包.toml` 的 TOML 子集解析器，零新依赖）：

```toml
索引版本 = 1

[包]
"工具@1.0.0" = { 来源 = "file:工件/工具-1.0.0", 校验 = "fnv1a64:06505cae7fb7fabb" }
"工具@1.1.0" = { 来源 = "https://example.com/工具-1.1.0.zip", 校验 = "fnv1a64:..." }
```

- `索引版本` 只认 `1`。
- 键是 `名字@主.次.修订`；同一名字+版本只能有一条，重复报 E132。
- `来源`：
  - 本地目录：相对索引文件所在目录，或 `file:` / 绝对路径；
  - 本地归档（2026-11-09 起）：路径指向一个文件（`.zip` / `.tar` / `.tar.gz`），用系统 `tar` 解包后再按目录哈希校验；`micc pack --源码` 产出的 `<包名>-<版本>-源码.zip` 就是这种形态；
  - `http(s)://` 归档：用系统 `curl` 下载，再交给系统 `tar` 解包（`.zip` / `.tar` / `.tar.gz`）。
- `校验`：H4 的目录内容哈希，`fnv1a64:` + 16 位十六进制；发布者用 `micc hash --目录 <包目录>` 生成。
- 索引只存元数据，不存包内容；内容必须另放在本地目录或可下载归档里。

依赖侧写法：`砾包.toml` 的 `[依赖]` **不写 `路径`** 就走索引：

```toml
[依赖]
工具 = { 版本 = "^1.0.0" }
```

`micc install --索引 <索引文件|URL>`；也支持把 `砾索引.toml` 放在包目录下、省略 `--索引`。
选版规则：满足约束的版本里取**最高**一个（`^1.0.0` 有 1.0.0/1.2.0/2.0.0 时选 1.2.0）。流程：
挑版本 → 取内容（本地复制或下载解包）→ 校验 H4 哈希 → 复制到 `.砾/包/` → 写锁。
索引包声明 `路径` 依赖会被拒绝（E126）：索引包只能依赖索引包。

**下载器**：没有引入 HTTP 依赖。`http(s)` 来源和远程索引都调用系统 `curl`；归档解包调用系统 `tar`。
Windows 10/11 自带 `curl.exe` 与 `bsdtar`；非 Windows 分支未验证（Linux 的 GNU tar 解 `.zip` 通常不行）。
本地目录来源不需要任何外部命令；**本地归档来源只需要 `tar`**（不联网）。

### 8.1 发布与检索（P2，2026-11-09）

`micc publish`：源码包 → 目录式仓库 → 索引条目。

1. 读 `砾包.toml` 取名字/版本；二进制包（有 `[包] 产物`）直接拒绝（E138）——`install` 消费不了预编译产物；
2. 用 `pack --源码` 的**同一份实现**产出归档，落到 `<仓库>/<名字>/<名字>-<版本>.zip`；
3. 把归档解包到临时目录算目录哈希：**索引里的 校验 取归档内容**，与 `install` 校验口径完全一致；
4. 读旧索引（若存在），替换同名字+同版本的条目，按名字/版本排序整体重写 `砾索引.toml`；`来源` 写成相对索引目录的正斜杠路径（跨盘符时退回绝对路径）。

默认 `--仓库` 是当前目录（只给 `--索引` 时取索引所在目录），默认索引是 `<仓库>/砾索引.toml`。
同版本重复发布幂等（归档覆盖、索引仍一条）；HTTP 索引只读，发布报 E138。

`micc search [关键词...] [--索引 <索引文件|URL>]`：读索引，对包名做「全部关键词都包含」的子串匹配（忽略大小写），
每个命中打印 `名字 版本 来源 校验`，按名字升序、版本降序；无命中打印说明并以退出码 1 结束；不带关键词列出全部条目。

限制（如实记录）：`publish` 只收顶层 `.jsh`（与 `pack --源码` 相同），包目录里的子目录/其它文件不会进归档；
索引由 `publish` 整体重写，**手写注释会丢失**。

## 9. 命令

```
micc pack [--目录 <包目录>] [-o 输出] [--离线] [--strip-debug] [--归档 [--源码]]
micc install [--目录 <包目录>] [--索引 <索引文件|URL>] [--离线]
micc hash [--目录 <包目录>]
micc verify <包目录|归档.zip>
micc interface --目录 <包目录> [-o 接口.toml]
micc publish [--目录 <包目录>] [--索引 <索引文件>] [--仓库 <目录>]
micc search [关键词...] [--索引 <索引文件|URL>]
```

- `pack` 默认输出 `<包目录>/<包名>.jmb`；`--目录` 默认当前目录。
- `pack --归档` 输出 `<包目录>/<包名>-<版本>.zip`（内含 `砾包.toml` + `<包名>.jmb` + `清单.toml`），
  并在输出目录同时落一份 `清单.toml` 与 `<包名>.jmb`，供 `micc verify <包目录>` 复用同一份元数据。
- `pack --源码` 输出 `<包名>-<版本>-源码.zip`（只含 `砾包.toml` + 本包所有顶层 `.jsh`，不含 `.jmb`/清单/zip），
  供 `micc install` 的索引来源直接消费；归档内容与 `micc hash --目录` 的口径一致。
- `pack` 成功时打印依赖列表、名字/常量/函数/类用量、字节码大小、堆下界、原生并集、输出路径。
- 二进制包（有 `[包] 产物`）没有源码：`pack` 直接拒绝并提示，`pack --归档` 只打包产物，`verify` 校验。
- `install` 成功时打印每个包的版本、来源与内容哈希；`--离线` 只做校验并打印锁条目。
- `hash` 打印目录内容哈希（`fnv1a64:...`），用于手写索引的 `校验`。
- `interface` 从**源码包**的入口 AST 生成 `接口.toml`（只列函数与参数个数；二进制包没有源码，直接拒绝）。
- `publish` 成功时打印归档路径/大小、校验、索引路径与条目总数；包目录若有未归档文件会额外提示。
- `search` 的 `--索引` 默认当前目录的 `砾索引.toml`；索引来源就是检索范围，不做跨仓库聚合。

## 10. 错误码

| 码 | 含义 |
|----|------|
| E124 | 打包后名字表超过 255（提示列出占用最多的包） |
| E125 | `砾包.toml` / 锁文件格式错误（字段、版本语法、缺失项、导出名/导出类型不存在） |
| E126 | 依赖解析失败：目录不存在、成环、同名不同目录、版本冲突、离线缺包/校验失败、索引包带路径依赖 |
| E127 | 依赖包顶层出现可执行语句 |
| E128 | 跨包引用未导出或私有的名字/类型，或类/枚举的跨包写法不对 |
| E129 | native 冲突：ABI 不一致、模块不存在、源码导入未声明的模块 |
| E130 | 静态预算超限：堆下界超过预算 80%，或 `.jmb` 超过字节码上限 |
| E132 | 索引不可用：读不了、`索引版本` 不是 1、条目字段缺失、条目重复、校验格式不对 |
| E133 | 索引里没有这个包 |
| E134 | 索引里没有满足版本约束的版本（提示列出索引现有版本） |
| E135 | 下载/解包失败：系统 `curl`/`tar` 不可用、HTTP 失败、来源不是目录或归档格式不支持 |
| E136 | 内容与索引不一致：哈希不符，或包名/版本与索引条目不符 |
| E137 | 归档/二进制包校验失败：缺清单、缺产物、大小或哈希不符、JMB 魔数/版本不符、调试段标记不符 |
| E138 | 发布失败：目标是 HTTP 索引、二进制包不能进索引，或仓库/索引写不了 |
| E144 | `私有` 用法错误：只能修饰模块顶层声明，不能重复，不能与 `[导出]` 冲突 |

## 11. 仍未覆盖（H4b 之后）

- **多 `.jmb` 链接：明确不做（2026-11-09 决定）**。理由三条：
  1. 链接器要把名字/常量/代码/类四张表按偏移重编号，还要重写每条指令里的索引操作数——等于在 `.jmb` 上再实现一层重定位，改错一位就是运行期崩溃；
  2. 源码级合并（H4a）已经能达成同样的组合效果，且共用一张名字表，没有跨模块索引；
  3. 二进制包定位是**分发预编译产物**（保护源码/省编译时间），不是组合多模块。二进制包因此不能声明依赖（本项目直接拒绝），跨包组合请用源码包。
- **接口清单只表达函数与类型轮廓**：`接口.toml` 从 LI016 起同时列 `[类.名字]`（字段、方法名/参数个数，含 `初始化`）与 `[枚举.名字]`（成员）；`micc verify` 会对照 JMB 类表检查类名、字段名、方法名与参数个数。**不表达**字段类型、方法返回类型与全局常量的类型；枚举是编译期常量，产物里没有对应表，因此只做表达、不校验。也不要求「导出的每个名字都必须出现在接口里」（导出里的非函数、非类型名字会被跳过）。
- **跨包继承**：`继承 包名.父类` 未支持（父类仍要求同一模块，E140）；可跨包的是 `新建 包名.类名`、类型标注与枚举成员读取。
- **目标板字段**：`砾包.toml` 暂无 `目标板`，烧录目标仍由构建脚本决定。
- **注册中心**：只有静态索引 + 目录式仓库；`micc publish` 只写本地归档与索引，没有上传接口、鉴权、服务端检索与跨仓库聚合。
- **索引签名与撤销**：索引与包内容只做哈希校验，没有签名、TUF/撤销机制；信任依赖索引所在位置（P2/N8 已明确不做，理由见路径图 §10.2）。
- **HTTP 依赖**：不引 HTTP crate，靠系统 `curl`；非 Windows 分支未验证。
- **锁更新策略**：没有 `micc update`，也没有最小版本选择；锁只由 `install` 全量重写。

## 12. 归档格式（H4b-1，2026-11-09）

`micc pack --归档` 产出 `<包名>-<版本>.zip`，ZIP 只用 **stored**（不压缩）——`micc` 自带最小 ZIP 读写（`compiler/src/zip.rs`），不引第三方 crate；条目名按 UTF-8（通用标志位 bit11）。

| 条目 | 内容 |
|---|---|
| `砾包.toml` | 原样复制，保证归档自描述（`micc verify` 从它取包名/版本/ABI/产物） |
| `<包名>.jmb` | 源码包：本次编译产物；二进制包：`[包] 产物` 指定的原文件 |
| `清单.toml` | 生成物，记录校验与兼容性信息（见下） |
| `接口.toml` | 可选：包目录里有它才打进去，记录导出函数的参数个数（见 §12.1） |

清单格式（UTF-8，`键 = 值`，`#` 注释）：

```toml
# 本文件由 micc pack --归档 生成，不要手改
清单版本 = 1
包 = "应用"
版本 = "1.0.0"
字节码版本 = 4
原生ABI = 2
产物 = "应用.jmb"
产物大小 = 3983
产物校验 = "fnv1a64:74faac68dd1b9d7c"
调试段 = false
```

- 校验用 **FNV-1a 64**（与锁文件、索引的 `校验` 同一格式）；不是加密哈希，只用于发现内容变化。
- `调试段` 是布尔，对应 JMB 头 `p5.bit0`；`--strip-debug` 归档时写 `false`。
- 归档同时会在输出目录落一份 `清单.toml` 与 `<包名>.jmb`，所以 `micc verify <包目录>` 与 `micc verify <zip>` 走同一套判断；这两个文件是生成物，删掉后重跑 `--归档` 即可恢复。
- `micc verify` 的检查项：清单必需字段与类型 → 包名/版本一致 → 产物名符合规范（源码包固定 `<包名>.jmb`，二进制包等于 `产物`）→ 大小 → FNV 哈希 → JMB 魔数/字节码版本 → 原生ABI → 调试段标记。任一不符报 E137 并以退出码 1 结束。
- 二进制包（`[包] 产物 = "x.jmb"`）允许的目录内容只有 `砾包.toml` + 产物（+ 归档产物 `清单.toml`/`.zip`）；声明 `[依赖]` 会被拒绝。
- 归档**参与** `micc install` 的索引来源解析：本地 zip/tar 与 `http(s)` 归档都会先解包、再按目录哈希校验（§8）。`verify` 只认**产物归档**（有 `清单.toml`）；源码归档会被明确提示「用 micc install 安装」。

### 12.1 接口清单（`接口.toml`）

`micc interface --目录 <源码包> [-o 路径]` 生成，默认写到包目录下的 `接口.toml`：

```toml
# 本文件由 micc interface 生成，不要手改
接口版本 = 1
包 = "库"
版本 = "1.2.0"
原生ABI = 2
字节码版本 = 5

[函数]
加一 = 1
问候 = 1

[类.计数器]
字段 = ["值"]
方法 = ["初始化/1", "加/1", "读/0"]

[枚举.状态]
成员 = ["空闲", "运行"]
```

- 来源是**入口源码的 AST**，不编译、不解析依赖；因此即使依赖暂时不可用也能生成。
- 有 `[导出] 名字` 时只列其中是顶层函数的名字；没有时列入口里所有公开函数。私有函数始终不列。
- 有 `[导出] 类型` 时只列其中是顶层类/枚举的名字；没有时列所有公开类型。私有声明始终不列。
- 参数个数取 `函数` / 方法声明的参数个数（方法不含 `本`），与实际 `.jmb` 代码表的 `nparams`（方法含 `本`，所以是 `nparams - 1`）由 `micc verify` 对照。
- 接口文件存在时会**随 `--归档` 一起打进 zip**，并在目录侧被 `verify` 读取；不存在时 `verify` 跳过该组检查（向后兼容旧归档）。
- `verify` 的接口检查：`接口版本 = 1`、包名/版本/原生ABI 与 `砾包.toml` 一致；函数在产物代码表里存在且 `nparams` 相等；类在产物类表里存在，列出的字段名存在，方法名存在且参数个数相等（`初始化` 对照类记录的构造代码）。任一不符报 E137。枚举只表达成员、不做校验（编译期常量，产物里没有表）。
