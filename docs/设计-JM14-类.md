# JM14（类）设计报告

> 状态：**已拍板并按推荐值实现**（2026-11-07）。§10 的 12 项全部采用推荐值；§11 记录拍板结果与实现前的两项实测结论。
> 依据：JM13 已提交（`ab3bad3`，JMB v3）；本报告给出 JM14 的语法、语义、内存、交互、资源、错误码与文档同步方案。
> 阅读顺序：先看 §10「必须由用户拍板」，其余章节是它的依据。

## 0. 结论摘要

- 语法：`类` 块 + `令 字段 = 默认值` + `函数 初始化(...)` / `函数 方法(...)`；`新建 类名(...)` 构造；`对象.字段` 读写；`对象.方法(...)` 调用；`本` 为方法内的只读自身引用。
- 语义：**不做继承、不做子类型多态**；保留结构化（鸭子类型）的字段/方法查找；字段默认值必填，在构造序言按声明顺序求值；访问未声明字段一律报错，不做自动扩展。
- 内存：新堆类型 `JM_T_INSTANCE=8`，固定字段布局 `JmObj + class_idx + 保留 3 B + JmValue fields[]`；类元数据全在 `.jmb`（Flash），不占 RAM；单实例含块头 `16+4n` 字节；沿用引用计数、无 GC，环引用泄漏作为已知限制文档化。
- 字节码：JMB 升 **v4**（头部 `p10 = nclasses`，代码表/捕获表之后追加类表）；新增 `OP_NEW_INSTANCE / OP_GET_FIELD / OP_SET_FIELD / OP_CALL_METHOD / OP_CALL_INIT / OP_RETURN_METHOD`。
- 资源：运行期 Flash 预估 +600~850 B（26.2~26.5 KB / 64 KB，约 41%）；RAM 静态 +8 B（14.65 KB / 20 KB，约 71.6%）；堆仍 6 144 B；MCU 栈余量 ~5.8 KB 不变。
- 错误码：运行期新增 E035~E037（字段不存在 / 非实例 / 方法不存在）；编译期新增 E118~E123；native 30~34 段不动，ABI 仍 v1。

## 1. 现状与约束（设计基线）

| 项 | 事实 |
| --- | --- |
| 值 | 4 字节，低 3 位标签；29 位整数；文本/列表/字典/迭代器/范围/小数/闭包在堆上 |
| 堆 | 静态 `jm_heap`，固件 6 144 B；块头 `JmBlk` 8 B，4 字节对齐，首次适配 + 前后合并 |
| 堆类型 | `STR=1 LIST=2 DICT=3 ITER=4 RANGE=5 DEC=6 CLOSURE=7`，**8 空闲** |
| 引用计数 | `JmObj{type,rc}`；`free_obj` 按类型递归释放；无 GC |
| 字节码 | JMB **v3**，12 B 头（p0-3 magic、p4 version、p5 flags、p6 nconsts、p7 nnames、p8 ncodes、p9 entry、p10/p11 空闲）；常量 8 B/项、代码表 10 B/项、捕获表 2 B/项；loader 严格只收 v3 |
| 调用约定 | `OP_CALL`：callee 在 `stack[sp-argc-1]`，`frame.base = sp-argc`，参数占 `base..base+nparams-1`，局部其后；`OP_RETURN` 释放 `cur_nlocals` 与 `base-1`，把返回值写回 `base-1`，`sp = base` |
| 错误码 | 运行期 1~29（E027~E029 为 JM13）；native 30~34；编译期 E102~E117 |
| 资源实测 | `异常` 固件：FLASH 25 616 B（39.09% / 64 KB）、RAM 14 644 B（71.50% / 20 KB）；堆实测空闲 5 596 B；SRAM 余 ~5.8 KB |
| 既有表态 | 路径图能力矩阵「类/继承/新建 ❌ JM14」；E103 文案把「类/继承」并列；D004 仍写「引入类/闭包后必须换标记清扫」 |

**已知文档债（本次同步时一并修订）**：`docs/路径图.md` 第 290 行仍写「静态堆 12 288 B」，与实际固件 `JM_HEAP_SIZE=6144` 不符；D004 的「必须换标记清扫」已被 JM12 闭包的现实（接受环泄漏、不换 GC）推翻。

## 2. 语法

### 2.1 完整形态

```jishi
类 计数器:
    令 值 = 0
    令 步长 = 1
    函数 初始化(起点):
        本.值 = 起点
    函数 加(n):
        本.值 = 本.值 + n * 本.步长
    函数 读():
        返回 本.值

令 c = 新建 计数器(5)
c.加(3)
打印(c.读(), c.值)      # 8 8
c.值 = 0                # 直接赋值
打印(c)
```

### 2.2 细则

| 元素 | 规定 |
| --- | --- |
| 声明位置 | `类` 只能出现在顶层（模块级），不能嵌在函数/块内（E118） |
| 类体 | 只允许 `令 字段 = 默认值` 与 `函数 名(参数):` 两种成员；其他语句 E118 |
| 字段声明 | 必须带默认值（与既有 `令` 一致），不允许裸声明；默认值可为任意表达式，但不得引用 `本`（E120） |
| 构造 | `新建 类名(实参...)`；实参对应 `初始化` 的形参；无 `初始化` 时只接受零实参 |
| 初始化 | 名为 `初始化` 的方法即构造函数；其中禁止 `返回`（E120），编译器隐式返回 `本` |
| 字段读 | `表达式.字段`，要求左侧求值为实例（E036）且类上声明过该字段（E035） |
| 字段写 | `表达式.字段 = 值`；复用既有赋值/复合赋值（`+=` 等）的解析与 DUP 机制 |
| 方法调用 | `表达式.方法(实参...)`；运行期按类表查找（E036/E037） |
| 本 | 方法内的只读绑定，指向当前实例；`本.字段` 可读可写，`本` 本身不可赋值（E120）；字段默认值里不可用（E120） |
| 方法名/字段名 | 各自的类内命名空间，不能被同名成员占用（E119）；`初始化` 为保留构造名 |
| 前向引用 | 类声明由预扫描收集（与既有函数一致），同一文件内可先 `新建` 后声明 |
| 关键字 | `类`、`新建`、`本` 转正；`继承` 仍是不支持关键字（E103），文案改为「使用了 v0 不支持的关键字（继承/最终/匹配等）」 |

### 2.3 与既有特性的关系

- **函数**：类方法不是全局函数、不占全局名字；编译为独立代码对象，`nparams = 声明形参 + 1`（槽 0 为 `本`），`nlocals` 同理。方法内的 `返回 值` 走 `OP_RETURN_METHOD`（§5.4）。
- **闭包**：方法体里可以写 `函数(): ...` 并捕获局部变量，也可以捕获 `本`（该闭包持有实例引用，是环泄漏的常见来源，见 §4.3）。
- **命名空间**：项目没有模块系统，类名与全局函数/全局变量共用顶层名字空间，重名在编译期报 E119；局部变量可与类名同名，但 `新建` 一律按类名静态解析，不查局部变量。
- **不做的语法**：继承、静态成员/类变量、私有成员、构造重载、方法重载、运算符重载、`删除 字段`。

## 3. 语义

### 3.1 继承：建议不做（需拍板）

路径图 D 系列与 E103 都把「类/继承」并列，但两者可以分开落地：

- **无继承**（推荐）：类之间只有组合关系（一个实例的字段可以指向另一个实例）。字段查找 = 单张类表线性扫描（字段数 ≤255，整数比较）；方法查找同样单层。
- **单继承**：类记录要加父类下标，字段/方法查找要沿父链走；字段布局要求父类前缀兼容；构造要串联父构造；还要定义覆盖、遮蔽与 `父`/`超级` 语法，测试面与文档面成倍增长，且没有 GC 时诊断更难。
- **代价对比**：单继承大约多 100~200 B Flash（查找循环 + 父链校验）和每类 1~2 B 元数据，但真正的成本在语义与测试；无继承则是 0 增量。

结论建议：JM14 只做「无继承的类」，`继承` 保持 E103；能力矩阵把「类/新建」改为 ✅，「继承」保持 ❌，路径图记为后续里程碑再评估。

### 3.2 多态

没有继承就没有子类型多态与虚表。保留的是**结构化多态**：字段与方法都在运行期按名字在实例的类表里查找，所以任何实例都能传进同一个函数，只要它声明了对应成员；缺失时报 E035/E037。文档需明确这是「运行期查成员」，不是编译期保证，也不是虚分派。

### 3.3 对象生命周期（构造流程）

`新建 C(实参)` 编译为：

1. `OP_NEW_INSTANCE C`：分配实例（`rc=1`），所有字段置 `空`，压栈；
2. 按源码顺序求值实参并压栈；
3. `OP_CALL_INIT C, argc`：校验 `argc+1 == init_code.nparams`（不符报 E012），建立方法帧（`base` = 实例所在槽），执行初始化代码。

每个类都有一份编译器合成的初始化代码对象（`init_code`），内容固定为：

1. 按声明顺序对每个字段执行「默认值表达式 → `SET_FIELD`」（因此默认值不能引用 `本`，也没有参数可用）；
2. 若用户写了 `初始化`，内联其函数体；
3. 末尾 `LOAD_LOCAL 0` + `OP_RETURN_METHOD`（隐式 `返回 本`）。

所以「无 `初始化` 的类」也走同一条路径，VM 不需要在 `NEW` 里求值默认值。构造表达式的值就是实例本身，`rc` 净值为 1（实例先作为栈临时值，随后成为方法槽 0；返回时 `LOAD_LOCAL` retain、`RETURN_METHOD` 释放槽 0）。

### 3.4 字段默认值

- 必填，按声明顺序求值一次（每次 `新建` 都求值，不做静态共享）。
- 允许任意表达式（可调用全局函数、可用全局变量、可建列表/字典/闭包），但不得使用 `本`。
- 因为类体没有裸字段名作用域，默认值之间不存在「引用别的字段」的隐式依赖。

### 3.5 未声明字段与错误

- **读**：`obj.未知` → 运行期 E035（`本.未知` 在方法内可静态判定，编译期 E122）。
- **写**：`obj.未知 = 值` → 运行期 E035（同样，`本.未知` 编译期 E122）。
- **非实例**：对整数/文本/列表等取字段或调方法 → E036。
- **方法不存在**：`obj.不存在()` → E037。
- **不做自动扩展**：不把实例当可变字典；字段集合在 `新建` 时固定，尺寸不随写入变化，避免堆重分配与布局漂移。
- 报错文案：为省 RAM 采用通用文案（如「实例没有该字段」），不带字段名；「代码 X 偏移 Y」后缀沿用既有排版。若后续需要在文案里带字段名，需再加 32~40 B 静态缓冲（列为可选代价）。

## 4. 对象表示与内存

### 4.1 堆类型与布局

```text
JM_T_INSTANCE = 8

typedef struct {
    JmObj   o;          /* 4 B: type=8, rc      */
    uint8_t class_idx;  /* 类表下标，≤255         */
    uint8_t reserved[3];/* 对齐到 4 字节           */
    JmValue fields[];   /* 4 n B，按类表字段顺序   */
} JmInstance;
```

- 前缀 8 B，字段从偏移 8 开始，天然 4 字节对齐。
- 单实例占用（含 `JmBlk` 8 B 块头）：`16 + 4n` 字节。
  - 3 字段 = 28 B；6 字段 = 40 B。
  - 堆空闲 5 596 B 时，空载可容纳约 200 个 3 字段实例，或约 139 个 6 字段实例（还要给文本常量留空间）。
- 字段存放的是普通 `JmValue`，实例对字段持有一份引用（赋值时 release 旧值、接管新值）。

### 4.2 类元数据：只进 Flash

类表放在 `.jmb` 里，运行期不复制到 RAM，只记录 `nclasses` 与 `class_start`（+8 B 静态）：

```text
类记录 8 B：
  +0 name_idx      u8   类名（名字表下标，用于 repr/报错）
  +1 nfields       u8
  +2 nmethods      u8
  +3 init_code     u8   初始化代码对象下标
  +4 fields_off    u16  相对 class_start
  +6 methods_off   u16  相对 class_start

字段区：nfields × u8（字段名下标）
方法区：nmethods × { u8 name_idx; u8 code_idx }
```

- 查找用整数下标比较，不做运行期 `strcmp`。
- 上限：`nclasses ≤ 255`、每类 `nfields ≤ 255`、`nmethods ≤ 255`；类名/字段名/方法名都占全局名字表（`nnames ≤ 255`，与全局名共享）。名字表耗尽沿用既有「名字过多」类错误，不新增机制。
- loader 载入时做边界校验（`fields_off/nfields`、`methods_off/nmethods`、各下标范围），越界报 E_FILE 而不是越界读。

### 4.3 引用计数与环引用（无 GC 的限制呈现）

- 实例是普通堆对象：容器（列表/字典）在 `free_obj` 时逐个 release；闭包在 `free_obj` 时 release 捕获槽；实例在 `free_obj` 时 release 全部字段；异常展开时操作数栈区间统一 release。级联自然成立。
- **环无法回收**：`本.自己 = 本`、或两个实例互指字段，`rc` 永远不会归零，对象静默泄漏，最终堆耗尽报 E017。
  - 建议策略：接受泄漏，并在语言卡「限制」与规格文档写明现象、给出规避写法（不要在实例字段里存回指自身/父级的引用）。
  - 备选（代价见 §10-D7）：运行期禁止「把自身赋给自己的字段」（只能拦住最直接的环，拦不住 A↔B，且给用户假安全感）；或上标记清扫（需要根集合扫描 + 标记位图，约 768 B RAM 与 600~900 B Flash，当前 RAM 余量不支持）。

### 4.4 实例在闭包与容器中的释放

- `令 f = 函数(): 打印(本.值)`：闭包捕获槽持有实例引用；闭包释放时实例 `rc--`。
- `列表.加入(c)` / `字典["k"] = c`：容器持有；容器释放或元素被覆盖时 `rc--`。
- 实例释放时字段里的容器/文本/闭包一并释放。
- 全局变量在 `jm_run` 生命周期内不主动释放（与既有一致），不额外处理。

## 5. 字节码与 JMB v4

### 5.1 头部与分段

- `p4 = 4`；`p10 = nclasses`；其余字段含义不变。
- 段落顺序：常量表 → 名字表 → 代码表 → 捕获表 → **类表** → 字符串池。
- `class_start` 由 loader 顺推（代码表 + 全部捕获表之后）。
- 版本策略沿用 D006（显式差异）：loader 只收 v4，旧 `.jmb` 报 E_FILE「需要 JMB v4」，必须重编译；不做 v3/v4 双路径。

### 5.2 新指令

| 码 | 名字 | 操作数 | 语义 |
| --- | --- | --- | --- |
| 32 | `OP_NEW_INSTANCE` | U8 类下标 | 分配实例（字段置 `空`，`rc=1`），压栈 |
| 33 | `OP_GET_FIELD` | U8 字段名下标 | 弹接收者；查类→报 E036；查字段→报 E035；retain 字段值、release 接收者、压栈 |
| 34 | `OP_SET_FIELD` | U8 字段名下标 | 弹「值」与「接收者」；同上校验；release 旧字段、接管新值、release 接收者 |
| 35 | `OP_CALL_METHOD` | U8 方法名下标, U8 argc | 弹参不动；接收者在 `sp-argc-1`；查类/查方法；进入方法帧 |
| 36 | `OP_CALL_INIT` | U8 类下标, U8 argc | 同 35，但方法固定取类记录的 `init_code`，并校验接收者类一致 |
| 37 | `OP_RETURN_METHOD` | 无 | 方法帧返回：释放 `base..base+nlocals-1`，把返回值写到 `base`，`sp = base+1` |

`OP_CALL_METHOD` / `OP_CALL_INIT` 的帧建立：

```text
栈： [接收者][实参1..实参N]        sp 指向最后一个实参之后
base = sp - argc - 1              → 接收者所在槽，即方法槽 0（`本`）
nparams（代码表） = 声明形参 + 1  → 校验 argc + 1 == nparams，否则 E012
nlocals 同理 +1
```

这样 `本` 就是普通的局部槽 0，`LOAD_LOCAL 0`/`STORE_LOCAL` 无需特殊处理；只有返回要用 `OP_RETURN_METHOD`（普通 `OP_RETURN` 会去释放 `base-1`，那属于调用方）。

### 5.3 类方法中的 `本`

- `本` 只读，不可作为赋值目标（E120）；`本.字段 = ...` 正常编译为 `LOAD_LOCAL 0` + 值 + `OP_SET_FIELD`。
- `本` 唯一绑定来源是方法帧槽 0；顶层/普通函数里出现 `本` 报 E120。
- `初始化` 内禁止显式 `返回`（E120），避免把构造结果变成 `空`；循环里允许 `中断/继续`。

## 6. 与既有特性的交互

| 场景 | 结论 | 说明 |
| --- | --- | --- |
| 实例进列表 | ✅ | 列表元素是 `JmValue`，push/retain 天然支持 |
| 实例作字典键 | ❌ 建议拒绝（E_KEY） | 与「可变值不作键」一致；若允许，则按身份比较，写入不改身份，技术上可行 |
| 实例作抛出值 | ✅ | `抛出` 接受任意值；未捕获时 `jm_repr` 打印 `类名{字段: 值}`，64 B 缓冲超长截断 |
| 被 `捕获` 后作值 | ✅ | 捕获变量是普通槽，实例生命周期按 RC 管理 |
| 真值判断 | ✅ | 已在堆分支默认返回 1（实例恒真） |
| 相等比较 | 身份相等 | `jm_equal` 对非文本堆对象先比指针；实例不做逐字段深比较 |
| `长度` / 索引 / 迭代 | ❌ | 实例不是容器；沿既有类型错误路径报错 |
| `类型(x)` | 「实例」 | 省事且稳定；不返回类名（`jm_type_name` 无状态参数） |
| native 边界 | 只能**入参透传** | `jm_value_kind` 返回 `JM_VK_OTHER`；v1 无构造/返回实例的 API，ABI 仍为 1，文档写明 native 不得返回实例 |
| 闭包捕获 `本` | ✅（建议允许） | 形成环即泄漏，文档提示 |
| 异常展开 | ✅ | 展开区间内的实例按栈释放；抛出值本身在 `OP_THROW` 中先转移所有权 |

## 7. 资源预估

| 项 | 预估 | 依据 |
| --- | --- | --- |
| 运行期 Flash | **+600~850 B** | 6 条指令 + 类表解析/边界校验 + 字段/方法查找 + repr/free/type_name + 3 条错误文案；JM13 三条指令实测 +516 B，本条目更多但查找逻辑短 |
| 运行期 RAM | **+8 B**（静态） | `nclasses` + `class_start`；方法帧复用既有 6 B 结构（无需加字段，靠 `OP_RETURN_METHOD` 区分） |
| 固件合计 | FLASH ≈ 26.2~26.5 KB / 64 KB（≈40~41%）；RAM ≈ 14.65 KB / 20 KB（≈71.6%） | 25 616 + 600~850；14 644 + 8 |
| MCU 栈余量 | ~5.8 KB 不变 | 只有 8 B 静态增量 |
| 堆 | 6 144 B 不变 | 类元数据在 Flash |
| 单实例 | `16+4n` B | 含块头 8 B |
| 每类 Flash | `8 + 字段数×1 + 方法数×2` B，另加名字表条目（2 B 偏移 + 字符串） | 类记录布局 |
| 编译器 | ~450~550 行、8 个文件 | §5.4 |

**风险**：实例数量受堆限制（5.6 KB 空闲只够百来个对象）；名字表 255 名额被类成员挤压；环引用泄漏；Flash 增量若超预算，优先砍字段/方法名下标比较外的诊断文案，而不是砍语义。

## 8. 错误码分配

| 代码 | 层 | 场景 | 文案草案 |
| --- | --- | --- | --- |
| E118 | 编译 | 类定义不在顶层；类体出现非字段/方法声明；字段声明缺默认值 | 「类体里只能写字段声明和方法」 |

## 10. 必须由用户拍板的选项

> 下表每行给推荐与代价；未拍板前不写实现代码。

| 编号 | 选项 | 候选 | 推荐 | 理由与代价 |
| --- | --- | --- | --- | --- |
| D1 | 继承 | ①无 ②单继承 ③无继承+组合 | **①** | 语义/测试/文档成本最小，Flash 0 增量；代价：用户需手工组合，`继承` 仍 E103 |
| D2 | 构造方式 | ①`初始化` 方法（可带实参） ②类名同名构造 ③仅字段默认值 | **①** | 与中文关键字风格一致、可带参数；代价：多一个保留成员名，禁止 `初始化` 内 `返回` |
| D3 | 方法是否一等值 | ①不支持（专用指令） ②绑定方法对象 | **①** | 不新增堆类型、调用快、释放简单；代价：不能把方法当回调传，`E123` |
| D4 | 未声明字段 | ①运行报错 ②自动扩展成可变对象 ③读空/写丢弃 | **①** | 固定布局、无重分配、抓拼写错误；代价：字段必须预先声明，`E035/E122` |
| D5 | 字段默认值 | ①必填且允许任意表达式（禁 `本`） ②可省略（默认空） ③只许常量表达式 | **①** | 无「未初始化字段」状态；代价：声明略冗长，默认值会在每次 `新建` 求值 |
| D6 | 实例打印 | ①`类名{字段: 值, ...}` ②`<类名>` | **①** | 与字典 `{k: v}` 一致、便于调试；代价：串口输出较长，64 B 未捕获缓冲会截断 |
| D7 | 环引用 | ①接受泄漏+文档 ②禁止自赋值字段 ③标记清扫 | **①** | 0 资源增量，与 JM12 闭包现状一致；代价：长期运行会 E017，需在语言卡显著提示 |
| D8 | JMB 版本 | ①升 v4 ②在 v3 上用 p10/p11 做可选扩展（向后兼容） | **①** | 单一路径、加载期显式拒绝混版；代价：旧 `.jmb` 全部重编译（与 v2→v3 相同） |
| D9 | native 边界 | ①不透明透传（ABI v1 不变） ②运行时拒绝实例入参 ③升 ABI v2 支持实例 | **①** | 零实现成本、ABI 稳定；代价：native 拿到 `OTHER` 无法读写字段，且文档禁止返回实例 |
| D10 | 命名空间 | ①类名进全局并禁重名，成员名进名字表（≤255） ②类/成员独立命名空间（成员名存字符串偏移） | **①** | 整数比较、实现短；代价：名字表 255 名额与全局/类成员共享，大程序会先撞名字表上限 |
| D11 | 字典键 | ①拒绝实例作键 ②允许（身份比较） | **①** | 与「可变值不作键」一致；代价：不能以对象为索引，需换成整数 id |
| D12 | 方法内闭包捕获 `本` | ①允许 ②禁止（E120） | **①** | 不额外限制、实现零成本；代价：容易写出环泄漏，需文档提示 |

**次要项（若无异议按推荐执行）**：`类型(实例)` 返回「实例」而非类名；`长度/索引/迭代` 不支持实例；实例相等按身份；类成员名上限 255。

## 12. 名字表余量（实现前实测）

读取既有 `.jmb` 头偏移 7（`nnames`）实测：

| 示例 | nnames |
| --- | --- |
| 你好 | 2 |
| 字典与比较 | 5 |
| 循环 | 5 |
| 堆压力 | 6 |
| 斐波那契 | 4 |
| 小数 | 7 |
| 列表 | 10 |
| 异常 | 11 |
| 闭包 | 19 |

加类之后：新示例 `examples/类.jsh`（3 个类、6 个字段、5 个方法 + 若干模块变量）实测 **nnames = 23**。

- 当前最大占用 23 / 255，**余量 232**。
- 结论：**沿用全局名字表（D10 的 ①），不引入「类名+成员名」局部子表**。余量充足；上限仍由 E105 兜底，不需要新机制。

## 13. 未捕获异常的 64 B 缓冲

采用 **截断 + 省略标记**（不加 RAM）：

- 缓冲仍是 `JmState.uncaught` 的 **64 字节**（实际字节数）。
- 预算：**60 B 正文 + 3 B「…」 + 1 B NUL**。
- 渲染超出 60 B 时置 `truncated`，退回到完整 UTF-8 字符边界（避免半个汉字），再补「…」，因此看到省略号即代表「还有内容没显示」。
- 语言卡「限制」表已写明该行为与字节数；`jm_repr` 的实例字段输出同样受此预算约束。
