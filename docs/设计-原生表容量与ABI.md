# 原生表容量与 Native ABI 扩容方案

> 状态：方案，未动代码。基线 `v0.1.0` / 提交 `94a9b27`。日期 2026-11-08。

## 0 结论

1. **当前不是「7 张表 / 25 项」，实测基线是 6 张表 / 21 项；PWM 落地后 6 张表 / 24 项；I2C 落地后 7 张表 / 28 项；JM8 收尾（队列销毁）后 7 张表 / 29 项。** 多出来的一张表和 4 项，对应 `任务` 模块：它的 `创建 / 删除 / 让出 / 延时` 四个函数已沉成 `OP_TASK_*` 操作码，不登记 native 表；`25` 这个数把 `信号量等待` 之类也算进去了。`docs/原生函数表.md` 当年的「七张表 23 项」旧账已按实测修正（见 §1.2）。
2. **`8 张表 / 64 项` 是运行期的策略常量，不是 C ABI 的一部分。** 抬高它们不需要 ABI v2，只改 `runtime/src/jm_native.c` 两个宏；代价是每多 64 项 +256 B RAM，表数上限几乎零成本。
3. **真正的硬上限是 8 位原生 id。** `JM_NATIVE_ID_BASE = 64`，id 是 `JmValue` 的 8 位段，所以最多 191 项；**128 项安全，192 项溢出**。这条才是「不能只改数字」的地方。
4. **推荐先并表、不升 ABI**：I2C 已按此落地新建 `总线`（4 项），PWM 并入已有的 `定时器`（3 项）。SPI 若再进 `总线`（约 3–4 项），落完是 **7 张表 / 31–32 项**，还余 1 张表 / 32–33 项；若同时把上限抬到 `12 / 128`，余 5 张表 / 96–97 项，够再撑 4–6 个硬件特性。
5. **ABI v2 的唯一真实触发点是「缓冲 / 句柄 / 中断上下文」，不是项数。** 参数字节数（≤8）和整数范围（±268,435,455）对 I2C/SPI/PWM 都不构成障碍；障碍是「多字节读要写进调用方缓冲区」和「返回设备列表」，见 §4。

## 2 并表能撑到多少

### 2.1 三个上限的真实性质

| 常量 | 位置 | 是什么 | 抬高代价 | 要不要升 ABI |
|---|---|---|---|---|
| 表数 8 | `jm_native.c:9` | 循环判定，不是数组长度 | 8→12 无实质成本 | 不用 |
| 项数 64 | `jm_native.c:10` | `g_entries[64]`，指针数组 256 B | 64→128：+256 B RAM；64→191：+508 B | 不用 |
| id 空间 | `jm_internal.h:382` + 8 位 id | 64..255 | 超过 191 项无处放 | 不用（.jmb 只存名字；id 是运行期内部约定） |

每个表项的边际成本：RAM 4 B（指针）；Flash = 名字字符串 + 20 B 静态 `JmNativeEntry` + C 代码。**项数本身很便宜**，8 位的 id 空间才是硬墙。

### 2.2 三个方案的项数账

新增功能的估算（按最小可用接口）：

- I2C：初始化、写（地址/寄存器/值）、读（地址/寄存器）、读多字节、扫描设备 = **5**
- SPI：初始化（速率/模式）、传输 1 字节、批量收发 = **3–4**
- PWM：启动（引脚/频率/占空比）、占空比、停止 = **3**（实测落地，无单独初始化）

| 方案 | 表数 | 项数 | 余量（对 8/64） | 能再撑几个特性 |
|---|---|---|---|---|
| **A. 全部新建 `总线`**（I2C+SPI+PWM 塞一张表） | 7 | 21+12=33 | 1 表 / 31 项 | 还能加约 31 项，但**只剩 1 张表**；下一个硬件特性若坚持「一特性一表」就撞墙 |
| **B. PWM 并入 `定时器`，I2C/SPI 新建 `总线`**（推荐） | 6 | 21+3+9=33 | 2 表 / 31 项 | 还能开 2 张新表；若继续并表，可再加 31 项 |
| **C. B + 上限抬到 12/128** | 6 | 33 | 6 表 / 95 项 | 4–6 个特性（按每个 5–15 项） |

结论：**并表能把「表数」这一维的墙往后推一到两张表**；项数在 64 以内都不是问题，硬墙是 191。若愿意改两个宏，C 方案在 RAM 上只多 256 B（当前余 3 412 B，抬完约 3 156 B，仍高于 3 000 B 警戒线）。

### 2.3 什么时候必须回头

1. 累计项数逼近 128（留 64 项给排障/未来）；
2. 需要同时开 5 张以上新表；
3. 需要把任一「一特性一表」的直觉改成「总线 + 函数名」；
4. 需要 192 项以上 —— 这时必须动 id 编码，也就是 ABI v2（见 §3）。

## 3 ABI v2 的真实代价

### 3.1 什么才算 ABI 破坏（必须升版本）

按 `runtime/include/jm_native.h:8-16` 的口径：

- 改 `JmNativeFn` 签名、参数语义、借用生命周期；
- 改 `JmValue` 的 tag / 29 位 payload / id 宽度；
- 改错误码（30–39）的含义；
- 允许原生函数保留指针、跨调用持有句柄（当前是「全借用」）；
- 增加「中断上下文可调用」的 `flags` 约定。

### 3.2 什么不必升版本

- 往已有表加函数（名字、参数个数都在编译期静态校验）；
- 新建表、增加表项；
- 抬高 `MAX_TABLES / MAX_ENTRIES`（运行期资源，不进 `.jmb`，也不进 C 签名）；
- 改实现、改文档、改错误文案；
- **新增只读访问器函数**（如 `jm_value_list_len/get`）——additive，不破坏既有函数。

### 3.3 逐文件波及面

| 文件 | 要改什么 | 对既有包/固件是否破坏 | 备注 |
|---|---|---|---|
| `runtime/include/jm_native.h` | 版本号、`JmNativeFn`、`JmNativeEntry` 布局、`JM_NATIVE_MAX_ARGS`、值访问器 | **是**（若动签名/值编码） | 21 个板级函数 + 14 个主机函数实现全部重写 |
| `runtime/src/jm_native.c` | 登记/绑定/分派、`MAX_TABLES`/`MAX_ENTRIES` | 仅容量：否；签名：是 | 存储 256 B → 512 B（128 项） |
| `runtime/src/jm_internal.h` | `JM_NATIVE_ID_BASE`、`JmValue` 编码 | 改 id 宽度=是 | 8 位 id → 191 项封顶 |
| `compiler/src/native_spec.rs` | 常量 `NATIVE_ABI_VERSION`、头文件生成、参数校验 | 编译器侧需同步 | 单点常量，改 1 行 + 重新生成头 |
| `compiler/src/langcard.rs` | `c_native_abi_version()` 漂移检查、JSON/ Markdown 三字段 | 需重生成 | 三字段：`bytecode_magic` / `bytecode_version` / `native_abi_version`；`abi_version` 已弃用、仅为旧消费者保留 |
| `spec/langcard.json`、`docs/语言卡.md` | 由 `micc --langcard` 重新生成 | 否（消费者只读） | `--check-langcard` 会拦漂移 |
| `compiler/src/pack_manifest.rs` | `砾包.toml` 的 `原生ABI`，缺省取编译器常量 | **是**（旧包缺省=1） | 没有 semver 区间，只有精确相等 |
| `compiler/src/pack.rs` | `check_native`（编译期 E129） | **是** | 旧包在 v2 编译器下直接编译失败 |
| `.砾/锁.toml` | **无 abi 字段**（`name/version/source/hash`） | 否 | 不需要迁移；顺便修正文档 183 行 |
| `firmware/stm32f103/f103_native.c`、`runtime/port/host/jm_host_native.c` | 表登记 + 35 个 C 函数 | 随头文件 | 板级 6 表 / 主机 5 表 |
| `docs/原生函数表.md`、`docs/包规范.md` | 契约、版本规则、项数表 | 否 | 必须同步，否则又出现 §1.2 的旧账 |
| `tools/test-native-import.ps1`（25）、`tools/test-packages.ps1`（23）、`--check-langcard` | 预期不变（名字/参数不动就全绿） | 否 | 若签名变，夹具的 C 侧桩要改 |
| `editors/vscode` | 只读 `spec/langcard.json` 的模块/字段 | 否 | 不改代码，只吃重新生成的语言卡 |

### 3.4 已发布包是否全部失效

- **机制上**：`砾包.toml` 不写 `原生ABI` 时，默认取编译器常量（`pack_manifest.rs:480`）；v2 编译器按精确相等比较（`pack.rs:345`），所有 v1 包会被 E129 拒绝，只能重打或手改 toml。
- **现实上**：当前没有 registry、`publish` 未实现、0.1.0 是首个版本，**外部包数量为 0**。所以此刻升 v2 的迁移成本≈0；等到 0.2.0 之后有真实包再升，成本会线性上升。

### 3.5 有没有必要 v1/v2 共存

没必要，且不建议：

- 原生表只服务于同一份固件里的 35 个函数，没有第三方原生模块；
- 共存要双 `JmNativeEntry` 布局、双绑定、双分派，Flash 余 29 KB 放得下，但测试矩阵和排障面翻倍；
- 真正需要兼容的是「已安装的包」，而它们的 ABI 只在编译期检查；一次性切换 + 清晰报错（E129 里写清「v2 要求，请重打」）比共存更省。

**结论：一次性切换，不做共存。**

## 4 I2C / SPI / PWM 的真实调用形状（第 4 条结论）

| 功能 | `.jsh` 形状 | 参数 | 返回 | 需要缓冲 | v1 够不够 |
|---|---|---|---|---|---|
| I2C 初始化 | `I2C初始化(100)`（kHz） | 1 整数 | 无 | 否 | 够 |
| I2C 写 | `I2C写(0x3C, 0x00, 0xAE)` | 3 整数 | 无 | 否 | 够 |
| I2C 读 1 字节 | `I2C读(0x3C, 0x00)` | 2 整数 | 1 整数 | 否 | 够 |
| I2C 读 N 字节 | `I2C读块(0x3C, 0x00, 8)` | 3 整数 | 8 字节 | **是（写入调用方）** | **不够** |
| I2C 扫描 | `I2C扫描()` | 0 | 设备列表 | 否（要建列表） | **不够**（无列表构造/追加入口） |
| SPI 初始化 | `SPI初始化(1000, 0)` | 2 整数 | 无 | 否 | 够 |
| SPI 传输 1 字节 | `SPI传输(0xA5)` | 1 整数 | 1 整数 | 否 | 够 |
| SPI 批量 | `SPI批量(数据文本, 长度)` | 1 文本 + 1 整数 | 文本 | 半 | 只读文本可以；输出要 `jm_value_make_text`，把二进制塞进「文本」是语义 hack |
| PWM 启动 | `PWM启动(22, 1000, 500)`（引脚, 频率赫兹, 占空比千分比） | 3 整数 | 无 | 否 | 够 |
| PWM 占空比 | `PWM占空比(500)` | 1 整数 | 无 | 否 | 够 |
| PWM 停止 | `PWM停止()` | 0 | 无 | 否 | 够 |

（PWM 已按此形状落地：并入 `定时器` 表共 3 项，没有单独的「初始化」——`PWM启动` 一次给齐引脚、频率、占空比。）

**结论：参数个数（≤3）、整数范围（12 位值 / 1 kHz–1 MHz 频率 / 千分比占空比，全部远小于 ±268,435,455）都不是障碍。** 唯一越界的是两类能力：

1. **多字节读要写进「调用方的缓冲区」**：v1 值全是借用且不可变，`jm_value_text` 只给 `const char*`，没有任何可写缓冲或列表写入口；
2. **返回列表**（如扫描结果）：v1 没有 `jm_value_make_list` / 追加接口，只有 `make_text`。

可选路径（按代价从低到高）：

- **① 单字节 API**：I2C/SPI 只暴露「读一个字节 / 写一个字节」，N 字节由 `.jsh` 循环。**零 ABI 改动**，代价是慢（每次一次函数调用 + I2C 事务）；
- **② 文本当字节流**：输入用 `jm_value_text` 只读借用，输出用 `jm_value_make_text` 造新文本。**不升 ABI**，但「文本」是 UTF-8 语义、`长度()` 按字符算，二进制数据会踩长度/打印的坑；
- **③ 新增只读列表访问器**（`jm_value_list_len/get`）：additive，按 §3.2 不算破坏，可放在 v1.1；列表本身仍由 VM 构造（`令 缓冲 = [0, 0, 0, 0]`），原生只读写元素；
- **④ 可写缓冲 / 句柄**：需要新的值种类或所有权约定，**这才是真正的 ABI v2**。

推荐先走 **①+③ 的组合**：PWM 全标量，I2C/SPI 先单字节可用，列表访问器作为 0.2.x 的增量；只有做屏幕、外部 Flash、文件这类批量 I/O 时再上 ④。

## 5 推荐路线与「什么时候必须升 ABI」

1. **现在（0.1.x）**：按方案 B 并表 —— PWM 已并入 `定时器`（3 项），I2C 新建 `总线`（4 项）；**不改上限、不升 ABI**。I2C 落地后实测 **7 表 / 28 项**（不是 §2.2 预估的 33 项，因为 I2C 实际只用了 4 项而不是 9 项）；JM8 收尾加 `队列销毁` 后为 **7 表 / 29 项**；SPI 已于 2026-11-09（N10）按 3 项并入 `总线`，落定为 **7 表 / 32 项**（5+2+6+5+3+4+7）。
2. **I2C/SPI 落地时**：若确认需要多字节，先加只读列表访问器（v1.1，additive）；若只需要单字节，则连这步都省。
3. **触发 ABI v2 的硬条件（任一出现即升）**：
   - 原生函数要保留指针 / 跨调用持有句柄；
   - 需要可写缓冲区或新的值种类；
   - 需要中断上下文直调（`flags` 约定）；
   - 需要 192 项以上（8 位 id 用尽）。
4. **升 v2 的顺序**（避免两侧漂移）：`native_spec.rs` 常量 → `jm_native.h` → `--emit-native-header` → 两个端口表 → `--langcard` 重生成 → `pack_manifest` 缺省 → 五套回归 + `test-native-import` → 文档（含修正 §1.2 的旧账）。
5. **不要做 v1/v2 共存。** 一次性切换，E129 文案写清「请用 v2 工具链重打包」。

## 6 实施时的验证清单

- `micc --check-native`、`micc --check-langcard` 零漂移；
- 五套回归（I2C 落地后实测，2026-11-08）：`test` 18/18、`test-errors` 38/38、`test-native-import` 33/33、`test-debug` 26 例 0 失败、`test-packages` 23 例 0 失败；
- 固件两档体积（OLED 文字示例，页缓冲 + 400 kHz，含 PWM 低频分频改动）：诊断开 FLASH 44 548 B / RAM 17 084 B；诊断关 FLASH 44 376 B / RAM 17 084 B；RAM 余 3 396 B（83.42% 已用）。相对 PWM 轮（38 084 / 37 916、RAM 17 068）是 FLASH +6 464 / +6 460 B、RAM +16 B。
- 上板验新增总线的最小闭环：I2C 已验证——扫描只命中 `0x3C`、走硬件 I2C2。耗时同一份页缓冲代码只换速率档实测（TIM2 1 MHz µs 计时 = 纯总线，SysTick `g_ms` = 墙钟）：128 B 单页 400 kHz **4.11 ms** / 100 kHz **16.36 ms**（比值 3.98，≈ 理论 4 倍）；1536 B 十二页突发 400 kHz **49.35 ms** / 100 kHz **196.3 ms**。寄存器 `I2C2_CR2 = 0x24`（APB1 = 36 MHz）、`CCR = 0x801E`、`TRISE = 0x0B` 证实 400 kHz 档真的是 400 kHz。SSD1306 驱动全部写在 `.jsh`。SPI 回环待做。
- PWM 审计（2026-11-08）：TIM4 实读 `PSC = 0x47`(71)、`ARR = 0x3E7`(999)、`CCR1 = 0x352`、`CCMR1 = 0x68` → 72 MHz / (72 × 1000) = **1000.00 Hz**，与请求一致。**没有 TIM2 那种 16 位静默截断**（超界是显式 `-1` → `E032`，不是静默变值）。低频端已改为 `ARR` 参与分频：1 Hz 实读 `PSC = 0xF9FF`(63999)、`ARR = 0x464`(1124) → 72 000 000 / (64000 × 1125) = **1.000000 Hz**（寄存器级证据）。全频段：1 / 10 / 100 / 1000 Hz 精确；5 kHz → 5142.86 Hz、10 kHz → 10285.7 Hz（+2.86%，`PSC` 整数取整导致，改前即有）。
