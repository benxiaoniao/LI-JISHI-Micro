# H6.2 Arduino 库形式桥接（LI025）

> 上游结论见 [H6.1-Arduino上传.md](H6.1-Arduino上传.md)：**把 Arduino 当上传通道不划算，独立 core 明确不做（X004）**。
> 本文只做剩下那条：把 `libjishim` + `jm_blob.c` 包成 STM32duino 能识别的库，让砾程序在 Arduino 工程里跑起来。

---

## 1. 做什么、不做什么

| | 内容 |
|---|---|
| 做 | 一个 Arduino 库（`library.properties` + `src/` + `examples/`）：`setup()` 里调用 `li::run()` 执行内嵌的 `.jmb`，`loop()` 空转 |
| 做 | 一条命令生成库目录与 zip：`tools/pack-arduino.ps1` |
| 做 | 主机侧验收：用 Arduino 兼容桩把库当普通 C/C++ 编译、链接、运行，输出与基准逐字节比对 |
| 不做 | 独立 Arduino core（`boards.txt` / `platform.txt` / variant），见 X004 |
| 不做 | 接管烧录：烧写仍由 `tools/flash-firmware.ps1`（ST-LINK / CubeProgrammer）负责 |
| 不做 | 把 Arduino 库塞进 `.jmb`：Arduino 库只能在 C/C++ 侧当外设驱动 |
| 不做 | 原生函数表：库只带运行时与端口，用到 `引脚 / ADC / 定时器 ...` 的 `.jsh` 会报 E012/E030 |

---

## 2. 产物结构

`tools/pack-arduino.ps1` 生成：

```
build/arduino/
  LiJishim/                     ← 直接拷进 ~/Arduino/libraries/
    library.properties
    src/
      LiJishim.h                包装头（li::run / li::lastError）
      LiJishim.cpp              包装实现（调用 jm_run）
      jm_port_arduino.cpp       端口：Serial / millis / delay / yield
      jm_blob.c                 内嵌的 .jmb（由 micc --emit-blob 生成）
      jm_vm.c jm_heap.c jm_builtin.c jm_loader.c
      jm_error.c jm_native.c jm_debug.c
      jishim.h jm_port.h jm_internal.h jm_native.h jm_native_table.h jm_opcodes.h
    examples/Hello/Hello.ino
  LiJishim-0.1.0.zip            ← 同样的目录，根是 LiJishim/
```

运行时 `.c` 是从 `runtime/src` **逐字节拷入**的，不是第二份实现；`test-arduino.ps1` 用 SHA256 比对确认同源。

---

## 3. 用法

```powershell
# 1. 先生成库（默认内嵌 examples/你好.jsh；也可以 -Example 小数）
.\tools\pack-arduino.ps1

# 2. 拷进 Arduino 库目录（Windows 示例）
Copy-Item build\arduino\LiJishim "$env:USERPROFILE\Documents\Arduino\libraries\" -Recurse

# 3. 打开 examples/Hello/Hello.ino，选板 STM32F103C8（STM32duino core）
#    编译用 Arduino，烧写仍用 tools\flash-firmware.ps1（ST-LINK）
```

草图只要两段：

```cpp
#include <LiJishim.h>

void setup() {
    Serial.begin(115200);
    delay(200);
    li::run();          // 跑内嵌的 .jmb
}

void loop() {
}
```

换程序 = 换内嵌的 `.jmb`：改 `-Example` 重新生成库（或只用 `micc --emit-blob` 覆盖 `src/jm_blob.c`）。

---

## 4. 端口映射

库只实现 [jm_port.h](../runtime/include/jm_port.h) 的四个钩子，其余全部复用 Arduino core：

| 钩子 | Arduino 侧 | 说明 |
|------|-----------|------|
| `jm_port_write` | `Serial.write` | 输出走用户 `Serial.begin()` 选定的串口与波特率 |
| `jm_port_millis` | `millis()` | `延时` / 定时器计数的时间基准 |
| `jm_port_sleep_ms` | `delay(ms)` | 阻塞式延时 |
| `jm_port_yield` | `yield()` | 让出（协作式） |

时钟、串口、GPIO 的初始化都留给 STM32duino core，库不碰寄存器、不设时钟、不改向量表。

## 5. 本机验收（不替代真机）

```powershell
.\tools\test-arduino.ps1
```

`tests/arduino/stub/` 提供最小 `Arduino.h`（`Serial`/`millis`/`delay`/`yield`），把库当普通 C/C++ 编译：

| 用例 | 内容 |
|------|------|
| 清单字段 | `name=LiJishim`、`architectures` 含 `stm32`、`includes=LiJishim.h` |
| 目录完整性 | 7 个运行时 `.c` + 4 个头 + 2 个 `.cpp` + `jm_blob.c` + 示例草图 |
| 同源性 | 拷入的 `.c` 与 `runtime/src` SHA256 一致 |
| 内嵌长度 | `jm_blob.c` 里 `jm_app_jmb_len` = `app.jmb` 字节数 |
| zip | 根目录是 `LiJishim/`，关键文件齐全 |
| 编译 | 8 个 `.c`（7 运行时 + blob）用主机 gcc 编过；4 个 `.cpp`（包装 + 端口 + 桩 + main）用 g++ 编过 |
| 链接与运行 | 链接成主机可执行文件，跑内嵌 `.jmb`，输出与 `tests/expected/你好.txt` 逐字节一致 |
| 失败路径 | `li::run(坏字节码, 4)` 返回 -1 且 `lastError()` 有文案 |

实测（2026-11-15，Windows）：

```
Arduino 库验收：14 项，失败 0 项
src 文件 18 个，共 190356 字节；内嵌程序：你好.jsh
压缩包 LiJishim-0.1.0.zip（51 624 字节）
```

`build.ps1` 已把这条并进回归；CI 的 `cross-platform` job 会跑（Linux 装了 `g++`）。

### 5.1 真实 Arduino 工具链验证（2026-11-15）

用本机安装的 **Arduino IDE 2.3.11** 自带的 `arduino-cli 1.6.0` 与 **STM32duino core 3.1.0** 实际编译：

```
画板：STMicroelectronics:stm32:GenF1:pnum=BLUEPILL_F103C8
命令：arduino-cli compile --fqbn ... --libraries <库父目录> --build-path <ASCII 临时目录> <Hello 草图>
结果：Sketch uses 44812 bytes (68%) of program storage space. Maximum is 65536 bytes.
      Global variables use 14032 bytes (68%) of dynamic memory, leaving 6448 bytes for local variables.
产物：Hello.ino.bin 45112 B / .elf 81840 B / .hex 126948 B
```

编译过程确认库被真正使用（`Used library LiJishim 0.1.0`），不是「文件在但没参与构建」。

真实工具链暴露了两个本机桩测不出来的问题，都已修：

| 问题 | 现象 | 处理 |
|------|------|------|
| 默认堆太大 | 首次链接 `region RAM overflowed by 1232 bytes`（F103C8 只有 20 KB） | 库内新增 `src/jm_config.h` 把 `JM_HEAP_SIZE` 定为 6 KB（与裸机固件一致）；`jishim.h` 用 `__has_include("jm_config.h")` 可选引入，不影响裸机与主机构建 |
| 中文工程路径 | `arm-none-eabi ld` 报 `cannot find .../crti.o`（路径被 ANSI 截断） | 属于工具链限制，不是库的问题：把库/草图/构建目录放到纯 ASCII 路径即可；已在 §6 写明 |

### 5.2 上板实测（2026-11-15）

用 ST-LINK（`STM32_Programmer_CLI`，SWD / Under Reset）把 `Hello.ino.bin` 烧到 `0x08000000`，校验与复位都成功；CH340 在 **COM4 / 115200 8N1** 抓到启动输出：

```
字节（去掉复位瞬间的 1 个噪声字节）：32 B
hex：e4 bd a0 e5 a5 bd ef bc 8c e4 b8 96 e7 95 8c ef bc 81 0a
     e5 9f ba e7 9f b3 20 e5 be ae 20 33 0a
文本：你好，世界！
     基石 微 3
```

与 `tests/expected/你好.txt` 内容一致（中文与数字相同）；两处可解释的差异：行尾是 `\n`（运行时的 `打印` 只发 LF，裸机端口也一样），基准文件在 Windows 上存成了 CRLF；复位后第一个字节是 `0xFF` 噪声（UART 起振），之后 32 字节完全对得上。日志：`build/uart/li025-arduino-clean.log`。

**未覆盖**：Arduino IDE 的「上传」按钮本身（core 的 upload recipe 未用），烧写仍由 ST-LINK / CubeProgrammer 完成，与 H6.1 的结论一致。

## 6. 已知限制

- **没有原生表**：`导入 引脚 / ADC / 定时器 / 队列 ...` 的 `.jsh` 编进库后运行会失败（运行期按名字找不到表）。要用外设，得把对应 `f103_*.c` 一起编进工程，或等后续把表做成可注册选项。
- **`loop()` 空转**：`li::run()` 在 `setup()` 里一次跑完；需要常驻循环的程序请用 `任务` + `延时` 写成阻塞式，或自行在 `loop()` 里调用 `li::run(指定字节码)`。
- **单实例**：`jm_run` 每次调用都会重置堆与执行状态，不能并行跑两份字节码。
- **堆上限**：库内 `src/jm_config.h` 默认 `JM_HEAP_SIZE = 6 KB`（F103C8 的 20 KB RAM 里要和 core 分）。要更大堆就改这个文件，同时确认板子 RAM 够用。
- **路径必须是 ASCII**：`arm-none-eabi` 链接器对中文路径会找不到 `crti.o`；库目录、草图目录、构建目录都放在纯 ASCII 路径下。
- **上传仍走 ST-LINK**：Arduino IDE 的上传按钮依赖具体 core 的 recipe，与 [H6.1](H6.1-Arduino上传.md) 的结论一致——不把上传当主通道。
