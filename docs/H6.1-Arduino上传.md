# H6.1 用 `arduino-cli` 上传砾固件（文档级）

> 结论：**能传，但不划算。** `arduino-cli upload` 本身不烧录，它只是按平台包的 `upload.recipe` 调外部烧录器。要拿到这条 recipe，必须先装 STM32duino 平台包（含 arm-none-eabi 工具链、CMSIS、HAL，**数百 MB 量级**）；而本仓库现有的 ST-LINK + CubeProgrammer 路径已经能做同一件事，且不依赖 Arduino 生态。
>
> 本页命令**未在本机执行**：当前环境没有 `arduino-cli`，也没有 `openocd`。文中给出的命令按 `arduino-cli` 的通用接口书写；带 `<...>` 的部分必须先用 `arduino-cli board details` 查实，不要照抄。

## 1. 需要什么板级定义

砾固件是**预编译的 `.bin`**，不需要 `.ino`，也不需要砾的 Arduino core。`arduino-cli` 只要求一个「板级定义（FQBN）+ 一个带上传 recipe 的平台包」。

- 板卡：STM32F103C8T6 最小系统板（Blue Pill）。
- 平台包：STM32duino（`STMicroelectronics:stm32`）。
- 常用 FQBN：`STMicroelectronics:stm32:GenF1:pnum=BLUEPILL_F103C8`。
- FQBN 的 menu 键（尤其是 `upload_method`）**随 core 版本变化**。先查：

```text
arduino-cli board details -b STMicroelectronics:stm32:GenF1
```

从输出的 `Option:` 列表里选 SWD 那条（不同版本可能叫 `STM32CubeProgrammer`、`ST-LINK` 等），记下它对应的 `upload_method=<值>`，不要凭记忆硬写。

## 2. 安装平台包（只为一条上传命令的代价）

```text
arduino-cli config init
arduino-cli config add board_manager.additional_urls https://github.com/stm32duino/BoardManagerFiles/raw/main/package_stmicroelectronics_index.json
arduino-cli core update-index
arduino-cli core install STMicroelectronics:stm32
```

体积说明：这不是「几十 MB 的小包」。STM32duino 平台包会连带下载 arm-none-eabi 工具链与整套 CMSIS/HAL，**数百 MB 量级**；具体字节数以安装时实际下载为准（本机未装，未实测）。如果只是想把 `jishim.bin` 烧进板子，装这套东西的收益接近 0。

## 3. 上传现有固件的等价命令

先构建（产物在 `build/stm32/jishim.bin`）：

```text
.\tools\build-firmware.ps1 -Example 外部中断
```

再用 `arduino-cli` 上传（把 `COM4` 与 `<swd方法>` 换成实际值）：

```text
arduino-cli upload -p COM4 `
  --fqbn STMicroelectronics:stm32:GenF1:pnum=BLUEPILL_F103C8,upload_method=<swd方法> `
  --input-file build\stm32\jishim.bin -v
```

- `--input-file` / `--input-dir` 是 `arduino-cli upload` 的「上传预编译产物」入口，不走 sketch 编译；以 `arduino-cli upload --help` 为准。
- 平台 recipe 通常引用 `{build.path}/{build.project_name}.bin`。`--input-file` 会把文件带进构建路径，工程名一般取自文件名（`jishim.bin` → `jishim`）；如果 verbose 输出里期望的文件名不同，用 `--input-dir` 放一个同名文件。
- 必须选 **SWD** 的 upload method。默认若是串口 bootloader（`BOOT0=1` + ST 内置系统 bootloader），这块板没有 Arduino bootloader，直接走串口会失败。

## 4. 与现有 ST-LINK + CubeProgrammer 路径的关系

两者是**同一个物理通道（SWD）上的两个前端**：

| 现有路径 | `arduino-cli` 路径 |
|---|---|
| [flash-firmware.ps1](../tools/flash-firmware.ps1) 调 `STM32_Programmer_CLI.exe` | `arduino-cli` 按 `upload.recipe` 调 STM32CubeProgrammer 或 OpenOCD |
| 命令：`-c port=SWD mode=UR -d build\stm32\jishim.bin 0x08000000 -v -rst` | 由平台包把同一组参数拼出来 |
| 不碰 option bytes；擦除交给工具默认策略 | 同样不碰 option bytes；擦除由 recipe 决定 |
| 产物：`jishim.bin/.hex/.elf` | 上传的仍是同一个 `.bin` |

换句话说，`arduino-cli` 没有新增烧录能力，只是把「CubeProgrammer/OpenOCD 命令行」换成了「平台包的 recipe」。既然现有脚本已经可用，**不建议为了上传去装 core**。

如果只想要一个不依赖 Arduino 的等价命令行，可用 OpenOCD（需自行安装，仓库未附带）：

```text
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg `
  -c "program build/stm32/jishim.bin 0x08000000 verify reset exit"
```

## 5. 不能混用的步骤（擦除 / 复位 / 选项字节）

1. **一次只开一个 SWD 会话。** CubeProgrammer GUI、`flash-firmware.ps1 -Apply`、`arduino-cli upload` 不要同时连 ST-LINK；后连的一方会拿到「目标被占用」或读到半写状态。
2. **不要整片擦除。** 现有脚本用 `-d ... 0x08000000` 下载，不做 `-e all`。整片擦除会连选项字节和任何已有的 bootloader 一起清掉；本板虽无 Arduino bootloader，也没必要动它。`arduino-cli` 的 recipe 若带 mass erase，改用 SWD 的「仅擦受影响扇区」方法。
3. **复位只在烧录末尾做一次。** 现有脚本用 `-rst`；`arduino-cli` 的 recipe 通常也会 `reset`。不要在上传中途手动按复位，也不要两个前端各复位一次。
4. **选项字节不归上传管。** 读写 option bytes 只能用 CubeProgrammer 的 `-ob` 系列；`arduino-cli` 不提供这个入口，任何「用 Arduino 改选项字节」的说法都不成立。
5. **串口 bootloader 与 SWD 不能混着来。** 若曾把 `BOOT0` 置 1 走串口上传，回到 SWD 前必须把 `BOOT0` 拨回 0 并复位，否则烧完仍进系统 bootloader，看起来像「上传成功但不运行」。
6. **前端切换后先校验。** 换前端后的第一次烧录，用 CubeProgrammer 只读模式 `-c port=SWD mode=UR -q` 确认芯片可连、读到的固件版本/入口正常，再继续。

## 6. 建议

- **默认继续用** `build-firmware.ps1 → flash-firmware.ps1`（ST-LINK + CubeProgrammer）。它已是仓库内可复现路径，CI 也在用同一套交叉编译产物。
- 只有在「机器上已经装了 STM32duino、且必须用 Arduino 工具链统一管理烧录」时，才按第 2–3 节走 `arduino-cli`；装 core 的几百 MB 是这条路的固定成本，不是砾固件需要的。
