# 性能基准（LI042）

> 目的：给解释器一个可复现的相对基准，优化前后用同一台机器、同一批工作负载对比。
> 不承诺绝对性能；只记录「改前 → 改后」的变化。

## 1. 方法

- 工作负载在 [tests/bench](../tests/bench)：`函数.jsh`（递归斐波那契）、`类.jsh`（实例方法循环）、`循环.jsh`（整数累加循环）。
- `jmrun --统计`（宿主专有）在 VM 取指处累加执行指令数，用单调高精度时钟测耗时，输出：
  `[统计] 指令 N 耗时 X ms 吞吐 Y 百万指令/秒`。
- `tools/bench.ps1` 编译每个工作负载，跑 3 次取最快一次（含进程启动），不参与固件。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/bench.ps1
```

## 2. 优化内容

不修改 JMB 格式、操作码编号或 ABI；旧 `.jmb` 原样可跑。

1. **宿主调试钩子快速路径**：`--dbg` / `--break` 都没给时，VM 不再每条指令调用
   `jm_host_break_hit` 与 `jm_host_dbg_tick`，只查两个全局标志。调试行为不变。
2. **整数快速路径**（宿主与固件共享）：`OP_BINOP` 的 `+` / `-` / `*` 与 `OP_CMP` 的六种比较，
   在操作数都是整数时直接内联计算，跳过 `jm_binop` / `jm_compare` 调用与两次 `jm_release`；
   其他类型、除法、溢出等仍走原路径。

## 3. 结果（Windows 主机，3 次取最快）

| 工作负载 | 指令数 | 改前耗时 | 改后耗时 | 耗时变化 | 改前吞吐 | 改后吞吐 | 吞吐变化 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 函数（fib 23） | 1 391 029 | 11.128 ms | 6.786 ms | **−39.0%** | 125.00 MIPS | 204.98 MIPS | **+64.0%** |
| 类（10 万次方法调用） | 2 600 031 | 17.434 ms | 10.484 ms | **−39.9%** | 149.13 MIPS | 248.00 MIPS | **+66.3%** |
| 循环（30 万次迭代） | 5 100 017 | 39.283 ms | 15.454 ms | **−60.7%** | 129.83 MIPS | 330.02 MIPS | **+154.2%** |

三个工作负载的耗时降幅都超过验收要求的 20%。

## 4. 目标侧

- 第 2 项（整数快速路径）编进共享 VM，固件同样生效；第 1 项只在宿主构建（`JM_HOST_DEBUG`）。
- 固件 `类`：**55 500 B Flash / 17 412 B RAM**（优化前 55 204 B / 17 412 B，**+296 B / +0 B**）。
- **板上计时待补测**：LI042 期间只做了主机基准；本机串口已接入，但尚未为板级吞吐/耗时做采集，因此不报板上数字。
