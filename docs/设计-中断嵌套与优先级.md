# 中断嵌套与优先级设计（LI020）

> 状态：**已实现并上板验证（2026-11-14）**。
> 关联：路径图 LI020（编号说明见 §0）；[调度模型.md](调度模型.md) §3 / §4；[设计-ABI-v2-中断直调.md](设计-ABI-v2-中断直调.md) §6；[原生函数表.md](原生函数表.md) §7.2
> 结论：**当前没有真正的应用中断嵌套**（所有 EXTI 同一个优先级，SysTick/PendSV 最低）；本设计把优先级固定成 4 个应用层 + 内核层，明确「谁能抢占谁、谁能调内核 API、谁能直调 native」，并补上启动期 SysTick 优先级设置过晚与注释错误两个缺陷。v1 不引入 BASEPRI，临界区继续用 PRIMASK。

## 1 现状（按仓库代码）

### 1.1 已配置的优先级

Cortex-M3 在 STM32F103 上实现 **4 个优先级位**（`NVIC_IPR` 高 4 位，低 4 位读 0）。`AIRCR.PRIGROUP` 保持复位值 0，即 **4 位全部用于抢占优先级，没有子优先级**；数值越小越紧急。

| 异常/中断 | 当前优先级 | 设置位置 | 说明 |
|---|---|---|---|
| HardFault | **-1（固定最高）** | 硬件固定 | 可抢占一切 |
| MemManage / BusFault / UsageFault | 0x00 | 复位默认 | `SHCSR` 未使能，实际**升级为 HardFault** |
| SVC | 0x00 | 复位默认 | 只在 `jmk_start` 里用一次 |
| EXTI（IRQ6–10 / 23 / 40） | **0x40** | `stm32f103_port.c` 的 `port_exti_bind` | 所有线同一个优先级 |
| SysTick | **0xFF**（读回 0xF0） | 端口层 `irq_init_priorities`（实现前在 `jmk_start`） | 从第一条 tick 起就是最低 |
| PendSV | **0xFF**（读回 0xF0） | 同上；`jmk_start` 复核 | 同上 |

代码位置：

- `firmware/stm32f103/jmk.c` 的 `jmk_start`：`SCB_SHPR3` 同时写 PendSV 与 SysTick 为 0xFF；
- `firmware/stm32f103/stm32f103_port.c` 的 `EXTI_IRQ_PRIO`（0x40）与 `port_exti_bind` 的 `NVIC_IPR_BYTE(irq) = EXTI_IRQ_PRIO`；
- `firmware/stm32f103/stm32f103_port.c` 的 `systick_init`：`STK_CTRL = 0x7` 直接使能 tick；
- `firmware/stm32f103/jmk.c` 的 `crit_enter/crit_exit`：保存/恢复 `PRIMASK`，`cpsid i`。

### 1.2 由此得到的实际行为

1. **EXTI 之间不能嵌套**：所有 EXTI 组都是 0x40，同优先级只能尾链（tail-chaining），不能互相抢占。
2. **SysTick/PendSV 不能抢占 EXTI**：0xFF 比 0x40 低。EXTI 执行期间 tick 会挂起，等 ISR 退出后再补。
3. **EXTI 可以抢占 SysTick/PendSV**：0x40 比 0xFF 高。这与 `jmk.c` 注释「SysTick 虽是低优先级，但外设中断仍可能抢占它」一致。
4. **SVC/HardFault 可以抢占 EXTI**：SVC 只在启动时用；HardFault 一旦发生，优先级最高。
5. **临界区会挡住所有中断**：`cpsid i` 不区分优先级，0x10 的紧急中断也要等临界区结束。

### 1.3 两个具体缺陷（已修复）

| 缺陷 | 实现前 | 影响 |
|---|---|---|
| SysTick 优先级设置过晚 | `port_init` 先 `systick_init` 使能 tick，`jmk_start` 才把 SysTick 写成 0xFF | 从 `port_init` 到 `jmk_start` 之间，tick 以 **0x00** 运行，可以抢占启动期的所有代码；窗口内 `jmk_current == NULL`，`jmk_tick` 会提前返回，所以没有崩溃，但优先级状态与设计不符 |
| 注释方向写反 | `EXTI_IRQ_PRIO 0x40u /* 低于 SysTick（默认 0），不比内核 tick 更急 */` | SysTick 最终是 0xFF，0x40 实际**高于** tick；注释会误导后续把外设优先级往 0x00 加 |

## 2 目标与非目标

### 2.1 目标

1. 给出一个可执行的**优先级分层**：谁高谁低、谁能抢占谁，一眼能查。
2. 明确每层 ISR 允许做什么：能不能调 `jmk_*_from_isr`、能不能 `jm_native_isr_call`、最长允许多少周期。
3. 让「中断嵌套」成为**受控能力**，而不是碰巧能发生：同层不嵌套，跨层按优先级抢占，嵌套深度有上限。
4. 修正 SysTick 优先级设置时机与错误注释。
5. 给后续外设中断（USART RX、ADC 完成、I2C/SPI 事件、定时器）提供固定的落位，不用每次重新讨论。
6. 不改 `.jmb`、VM、操作码、Native ABI；只动固件端口层与文档。

### 2.2 非目标

- 不做运行期动态改优先级（`.jsh` 不暴露 `设置优先级`）；
- 不做优先级继承 / 互斥量（信号量没有持有者，另立项）；
- v1 不把临界区改成 `BASEPRI`；
- 不做「每个任务一个 VM」或中断里跑字节码；
- 不改变现有 EXTI 的默认优先级数值 0x40（避免行为回归）。

## 3 方案比较

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 维持现状，只改注释 | 所有 EXTI 0x40；不引入分层 | 零风险 | 第二个外设中断到来时还得重新设计；无法回答「能不能嵌套」 | 不做 |
| B. 固定 4 层 + 编译期常量 | 定义 `PORT_PRIO_*`，EXTI 落 NORMAL；不加运行期 API | 成本最低；行为与现状兼容；文档即契约 | 新增外设时要改常量并重新编译 | **采用（v1）** |
| C. 运行期优先级 API + 分层校验 | `port_irq_set_priority(irq, prio)`，拒绝内核向量与非法层 | 板级包可自行配置 | 多一层校验与测试面；当前只有一个外设中断源 | 预留接口，**v1 只做最小实现** |
| D. BASEPRI 临界区 + 高优先级 ISR 不被屏蔽 | 临界区只屏蔽 ≥ 阈值的 IRQ | 紧急层延迟更短 | 内核状态与高优先级 ISR 的互斥要重新证明；现有 `_from_isr` 全部依赖 PRIMASK | v1 不做 |

## 4 优先级契约

### 4.1 分层表

只使用下面 5 个值，其余值保留（给未来细分，不要随手填）：

| 层 | 数值 | 用途 | 能否 `_from_isr` | 能否 `jm_native_isr_call` | 执行预算（建议） |
|---|---|---|---|---|---|
| 故障 | -1 / 0x00 | HardFault；SVC 仅启动 | 否 | 否 | 必须终止或复位 |
| 紧急 | **0x10** | 需要最短响应的外设（当前无） | **否** | **否** | < 2 µs |
| 普通 | **0x40** | EXTI、现有外设中断 | **是** | **是**（仅 ISR-safe 项） | < 20 µs |
| 慢速 | **0x80** | 可延后的外设（未来 UART RX、ADC 完成） | **是** | 建议否 | < 100 µs |
| 内核 | **0xFF**（读回 0xF0） | SysTick、PendSV | 是（自身） | 否 | 固定，不可改 |

> STM32F103 只实现优先级字节的高 4 位：写入 `0xFF` 读回 `0xF0`，两者是同一档。上板自检会看到 `0xF0`，这是硬件行为，不是配置错误。

常量建议放在 `firmware/stm32f103/stm32f103_port.h`：

```c
#define PORT_PRIO_FAULT     0x00u
#define PORT_PRIO_CRITICAL  0x10u
#define PORT_PRIO_NORMAL    0x40u   /* EXTI 默认 */
#define PORT_PRIO_SLOW      0x80u
#define PORT_PRIO_KERNEL    0xFFu
```

`EXTI_IRQ_PRIO` 改为 `PORT_PRIO_NORMAL`，数值不变。

### 4.2 抢占规则

1. **数值更小才能抢占**。0x10 可抢占 0x40，0x40 可抢占 0x80，0x80 可抢占 0xFF；反向不行。
2. **同层不嵌套**。同一优先级的中断只能尾链；`exti_serve` 一次处理本组全部挂起位。
3. **内核向量固定**。SysTick、PendSV 永远是 0xFF；SVC 只在启动期使用，默认 0x00；HardFault 固定 -1。
4. **应用 ISR 不得直接写 `NVIC_IPR` / `SCB_SHPR` / `SCB_SHCSR`**；需要改优先级时只走端口层的 `port_irq_set_priority()`（见 §4.3）。
5. **最大嵌套深度 = 3 层应用中断**（紧急 → 普通 → 慢速）。HardFault 可以再叠一层，但故障处理不返回。

### 4.3 最小配置接口

v1 只需要一个受控写入点，避免各外设各写各的：

```c
/* irq 是 NVIC 中断号（0..67）；返回 0 成功，-1 非法 irq 或试图改内核向量。
 * 实现时只写高 4 位：NVIC_IPR_BYTE(irq) = prio & 0xF0u。 */
int port_irq_set_priority(uint32_t irq, uint8_t prio);

/* 只读，给启动自检与 SWD 排障用。 */
uint8_t port_irq_get_priority(uint32_t irq);
```

约束：

- `irq` 必须是外部中断号；SVC/SysTick/PendSV 不在 NVIC 中断号空间里，天然被排除。
- `prio` 只接受 **0x10 / 0x40 / 0x80** 三个应用层值；0x00 与 0xFF 分别留给故障与内核向量，传入返回 `-1`。
- `port_exti_bind` 统一走这个接口，把 0x40 写死的历史收口到一处。

### 4.4 启动顺序

已实现的启动顺序（`port_init`）：

```text
clock_init
  → uart_init
  → 设置 SysTick/PendSV 优先级（0xFF）+ SVC（0x00）
  → systick_init（使能 TICKINT）
  → GPIO 初始化
```

`jmk_start` 里保留一次 `SCB_SHPR3` 复核（防御性，不改变值）。这样从第一条 tick 起就是最低优先级，消除 §1.3 的启动窗口。

## 5 各层的允许动作

### 5.1 紧急层（0x10）

- 只允许：读/写单个寄存器、清挂起、置标志、写一个 `volatile` 计数。
- **禁止**：`jmk_*`（含 `_from_isr`）、`jm_native_isr_call`、`port_log`、任何循环等待、任何分配。
- 理由：这一层的存在意义是「比内核 tick 和普通外设都急」；调内核 API 会走 `PRIMASK` 临界区，反而把这一层自己和其他更高层挡住。

### 5.2 普通层（0x40）

- 现有 EXTI 落在这里。
- 允许：`jmk_queue_send_from_isr` / `jmk_sem_post_from_isr`；`jm_native_isr_call` 调 ISR-safe 项（`引脚读/写/翻转`、`定时器计数`、`PWM占空比`）。
- 禁止：阻塞、分配、文本/容器、`jm_native_fail`、`jm_run`。
- 预算：ISR 总时长 < 20 µs（72 MHz 约 1 440 周期）。已知 `引脚翻转` 直调量程 **326–331 周期**（含插桩），加上异常入栈/出栈与 `exti_serve` 循环，仍在预算内。

### 5.3 慢速层（0x80）

- 允许：`_from_isr`、环形缓冲搬运、置标志。
- **不建议**直调 native：这一层的目的就是「可以被普通层延后」，直调省下的延迟在这里价值不大，反而扩大审计面。
- 预算 < 100 µs；超过就应拆成「ISR 搬运 + 任务处理」。

### 5.4 内核层（0xFF）

- SysTick 只做 `g_ms++` 与 `jmk_tick()`；`jmk_tick` 内部用 `PRIMASK` 保护就绪队列与等待链。
- PendSV 只做上下文切换；不做业务。
- 二者同优先级，不能互相抢占；外设 ISR 可以抢占它们，所以 `jmk_tick` 的临界区必须短。

### 5.5 故障层

- HardFault 固定 -1，能抢占任何 ISR；处理函数**不得返回**。
- v1 不使能 MemManage/BusFault/UsageFault 独立向量，继续升级为 HardFault，减少一层优先级与处理分支。
- 建议实现时把 `Default_Handler` 的 `b .` 换成可诊断的 `HardFault_Handler`：读 `SCB->CFSR/HFSR/MMFAR/BFAR`，用轮询 UART 打印后停机。这样「卡死」至少能留下现场。

## 6 嵌套边界与共享状态

### 6.1 任务被随时打断

任务可能在字节码指令之间、普通 native 内部、`jm_native_call` 参数检查期间被 ISR 打断。ISR 只允许碰：

- 单字节/单字的 `volatile` 状态（`g_ms`、`g_exti_count[]`、`g_pin_out[]`）；
- 内核 `_from_isr` API（内部有 `PRIMASK` 临界区）；
- ISR-safe native 的固定寄存器路径。

不得依赖 `JmState`、VM 值栈、堆、文本对象。

### 6.2 同层与跨层

| 场景 | 行为 | 依据 |
|---|---|---|
| 两条 EXTI 同为 0x40，同时挂起 | 不嵌套；先处理一条，再尾链另一条 | 同优先级不抢占 |
| 0x10 的 ISR 执行中来了 0x40 | 0x40 挂起，等 0x10 退出 | 数值小的优先 |
| 0x40 的 ISR 执行中来了 0x10 | 0x10 立即抢占，深度 2 | 数值小的优先 |
| 0x80 执行中来了 0x40 | 0x40 抢占，深度 2；若 0x10 再来则深度 3 | 分层抢占 |
| 0x40 执行中来了 SysTick（0xFF） | tick 挂起，ISR 退出后补 | 内核最低 |
| 0x40 执行中来了 HardFault | HardFault 立即抢占，不返回 | 固定最高 |

### 6.3 临界区

- v1 继续用 `PRIMASK`：`crit_enter` 保存、`cpsid i`、`crit_exit` 恢复。
- 代价：0x10 紧急层也会被临界区挡住，最坏延迟 = 最长临界区（就绪队列/等待链的几十条指令）。
- 规则：临界区内不做循环、不打印、不调用 native；临界区只包住链表指针操作。
- 如果将来出现「必须在 1 µs 内响应、又不能等临界区」的硬实时源，再评估 `BASEPRI` 阈值方案（方案 D），不在 v1 做。

### 6.4 栈

- 启动后 MSP 专供异常与 ISR，链接脚本至少保留 **2 KB**（`_Min_Stack_Size = 0x800`）。
- 单层异常开销：硬件帧 32 B + 编译器保存的 callee-saved 寄存器 + 局部变量；按 96 B/层估算，3 层应用嵌套 + 1 层故障约 400 B，仍有充足余量。
- 验收时用 MSP 哨兵扫描实测峰值，不靠估算（见 §8）。

## 7 错误与观测

ISR 里没有 VM 错误通道（同 ABI v2 §7）。本设计的观测手段：

1. **启动自检**（debug 构建）：打印 `NVIC_IPR[6,7,23,40]`、`SHPR2`、`SHPR3`，与 §1.1 的表对照。
2. **嵌套深度计数**（debug 构建）：在 `exti_serve` 入口/出口维护 `g_isr_depth` 与 `g_isr_depth_max`，任务上下文打印峰值；正常应 ≤ 3。
3. **错误计数**：现有 `g_isr_native_errors` 已覆盖直调失败；再加一个「非法优先级配置」计数（`port_irq_set_priority` 返回 -1 时）。
4. **故障现场**：HardFault 打印 `CFSR/HFSR/MMFAR/BFAR` 与 `LR`、`PC`、`xPSR`。

这些都属于板级/调试构建，不进入 `.jsh`，不增加 Native ABI 表项。

## 8 验证计划

### 8.1 寄存器与启动顺序

- 启动自检打印：EXTI 四个向量均为 0x40；SysTick/PendSV 为 0xFF；SVC 为 0x00。
- 用 SWD 直接读 `NVIC_IPR6/7/23/40` 与 `SHPR2/SHPR3` 复核。
- 复位后立刻观察：tick 不应在 `port_init` 到 `jmk_start` 之间以 0x00 运行（改前/改后各测一次）。

### 8.2 同层不嵌套

- 绑定两条同组 EXTI（例如 PA0/PA1，都是 0x40），同时软件触发；
- 断言：`g_isr_depth_max == 1`；两条计数各 +1；队列收到 2 条事件；
- 预期：尾链，不出现「A 入口 → B 入口 → B 出口 → A 出口」。

### 8.3 跨层抢占

- 临时把一条线设为 0x10（仅测试构建），另一条 0x40；
- 在 0x40 的处理里软件触发 0x10 那条；
- 断言：顺序为「普通入口 → 紧急入口 → 紧急出口 → 普通出口」，`g_isr_depth_max == 2`；
- 再叠一条 0x80，验证最大深度 3。

### 8.4 内核延迟

- 在 0x40 ISR 内忙等 N 个周期（N 取 1 000 / 5 000 / 10 000），用 DWT 记录「SysTick 挂起到 `jmk_tick` 开始执行」的差值；
- 断言不超过预算（普通层 < 20 µs），并记录最坏值；
- 直调路径已有约 326–331 周期基线，可直接作为 N 的一部分。

### 8.5 栈与故障（已做，2026-11-14）

- `JM_MSP_WATERMARK=1`：启动时把 `[_ebss, MSP-256)` 填 `0xA5`，10 000 次嵌套触发后扫描；实测 **280 B / 3044 B**，余量 2764 B。
- `JM_FAULT_DEMO=1`：执行 `udf #0`，HardFault 打印 `EXC_RETURN/MSP/PSP/CFSR/HFSR/MMFAR/BFAR/PC/LR/xPSR` 后停机；实测 `CFSR=0x00010000`、`HFSR=0x40000000`，MMFAR/BFAR 无效位显示 `-`。

### 8.6 回归

- 五套主机回归不变（本设计只动固件端口层）；
- `build-firmware.ps1 -Example 外部中断` 与 `-Example 类` 交叉编译；
- 上板跑 `外部中断.jsh`，队列计数、`中断计数`、解除语义与 ABI v2 轮次一致；
- 记录体积增量（预期只有几十到几百字节 Flash，RAM 不变或 +几字节）。

## 9 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 紧急层调内核 API | `PRIMASK` 把紧急层自己也挡住，实时性反而变差 | 明确禁止；代码评审 + 文档 |
| 嵌套深度失控 | MSP 溢出，HardFault 现场丢失 | 固定 3 层；debug 深度计数 + MSP 哨兵 |
| 临界区变长 | 高优先级中断延迟抖动 | 临界区只做链表操作；测量最坏值 |
| 优先级数值被随手填 | 出现未定义的层，抢占关系不可预测 | `port_irq_set_priority` 只接受 0x10/0x40/0x80 |
| 启动期 tick 优先级 | 启动窗口内 tick 以最高优先级运行 | §4.4 调整顺序；保留 `jmk_start` 复核 |
| 故障处理改动 | 新 handler 自身有 bug，二次故障 | 已加 HardFault 现场打印；UART 未初始化时直接停机；只读故障寄存器，不改复位策略 |
| 与 ABI v2 直调规则冲突 | 有人把直调放进紧急层 | 本文限定「仅普通层」；ABI 文档同步一句引用 |

## 10 实施顺序

1. `stm32f103_port.h`：新增 `PORT_PRIO_*` 常量与 `port_irq_set_priority/get_priority` 声明；
2. `stm32f103_port.c`：
   - 加 `port_irq_init_priorities()`，在 `systick_init` 之前设置 SysTick/PendSV 为 0xFF、SVC 为 0x00；
   - `EXTI_IRQ_PRIO` 改用 `PORT_PRIO_NORMAL`，修正注释；
   - `port_exti_bind` 改走 `port_irq_set_priority`；
   - 实现只读 `port_irq_get_priority`；
3. `jmk_start`：保留 `SCB_SHPR3` 复核，删掉「首次设置」的语义（值已在端口层设好）；
4. debug 构建：启动自检打印优先级表；`exti_serve` 加深度计数（宏控制）；
5. 测试构建：两条 EXTI 跨层抢占夹具 + DWT 延迟测量；
6. 上板：同层尾链、跨层抢占、内核延迟、MSP 水位、故障现场；

8. 五套回归 + 体积记录。

## 12 实施结果（2026-11-14）

|---|---|
