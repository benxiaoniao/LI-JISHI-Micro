# 原生函数表（Native ABI v1）

> 面向：写 native 模块的人（C 侧）、写包管理器的做法（H4）、Arduino 桥接（H6.2）
> 代码：`runtime/include/jm_native.h`（对外契约）　`runtime/src/jm_native.c`（登记与分派）
> 版本：`JM_NATIVE_ABI_VERSION = 1`　更新时间：2026-11-07

---

## 1. 为什么先定 ABI

砾的硬件能力（`引脚.写`、`定时器.延时`、`adc.读`）不是运行时自带的内建，而是**由板级 C 模块提供**。这条边界一旦不确定，后面三件事都会变形：

- **H4 打包**：包里要写明「依赖哪个 native 表、版本多少」，锁文件才能还原出同一套符号；
- **H6.2 Arduino 桥接**：`setup()` 里只调一次 `jm_run`，外设驱动以 native 函数的形式接进来；
- **JM7 硬件绑定**：同一份 `.jsh` 在主机端口和 F103 上必须表现一致，差别只允许在 native 层。

所以先把签名、值读写、错误传播、可重入与中断规则钉死，再往表里填函数。

---

## 2. 分层与边界

```
砾源码 .jsh ──micc──▶ .jmb（只有名字，没有函数地址）
                          │
                          ▼
        jm_run：读名字表 → 内建(0..63) / 原生(64..127) 绑定到全局
                          │
                 ┌────────┴─────────┐
                 ▼                  ▼
        runtime（C99，可移植）   native 表（板级模块，可由第三方包提供）
        值/堆/VM/错误               GPIO / ADC / 定时器 / 外设库
```

三条硬边界：

1. **`.jmb` 里只放名字**，不存函数地址、不存 ABI 序号。绑定发生在 `jm_run` 时，找不到就是 `E004 名字未定义`。
2. **native 层不碰 VM 内部**：不解析值标签、不直接读写 `JmState`，只走 `jm_native.h` 里的函数。
3. **native 层不链进宿主工具链**：它是固件的一部分，随 `.jmb` 一起发布的是「包 + native 模块」，不是语言卡。

## 3. 登记与绑定

```c
typedef int (*JmNativeFn)(JmStateRef st, const JmValue *args, uint8_t nargs,
                          JmValue *out);

typedef struct {
    const char *name;
    JmNativeFn fn;
    uint8_t min_args;
    uint8_t max_args;
    uint8_t flags;     /* 保留，v1 必须为 0 */
    uint8_t reserved;  /* 保留，v1 必须为 0 */
} JmNativeEntry;

int jm_native_register(const JmNativeEntry *entries, uint8_t count);
```

规则：

| 规则 | 说明 |
|---|---|
| 登记时机 | `jm_run` 之前，任意次；通常放在板级初始化里，比 `jm_run` 早一行 |
| 容量 | 最多 8 张表、共 64 个表项（`JM_NATIVE_MAX_TABLES` / `JM_NATIVE_MAX_ENTRIES`） |
| 重名 | 视为登记失败（返回 `-1`），不做「后者覆盖」；名字冲突属于打包错误 |
| 保留位 | `flags`/`reserved` 非 0 → 登记失败。这是给未来 ISR 直调留的位置，现在不猜 |
| 生命周期 | 表必须是静态存储期（`static const`），运行时不复制表项 |
| 未绑定 | 名字在 `.jmb` 里但没人绑 → 与普通未定义名字同一条错误路径 |

绑定顺序：先内建（`打印`、`文本`…10 个），再原生表。原生表**不得**与内建重名。

## 4. 参数传递

| 项 | 约定 |
|---|---|
| 顺序 | 源码实参自左向右，`args[0]` 是第一个实参 |
| 个数 | `nargs ∈ [min_args, max_args]`，运行时在调 `fn` 之前检查；越界报 `E012` |
| 上限 | 单次最多 8 个（`JM_NATIVE_MAX_ARGS`）；更多的参数应由编译器侧拦下 |
| 所有权 | **全部借用**。native 不得 `retain` 后长期保存，也不得保存 `args` 指针 |
| 类型 | 不做隐式转换。要整数就 `jm_value_to_int`，失败按 `JM_NE_TYPE` 报错 |
| 缺省 | 可选参数用 `min_args` 表达，native 内部按 `nargs` 分支；**没有默认值机制** |

`args` 指向 VM 值栈上的连续区域，返回后即失效。若确实要带走（比如缓存最后一次读数），必须 `jm_value_retain`，并在自己销毁时 `jm_value_release`。

---

## 5. 返回值

| 项 | 约定 |
|---|---|
| 出口 | `*out`，成功时必须写；失败时**不保证**有值，运行时会丢弃 |
| 构造 | 只用 `jm_value_int` / `jm_value_bool` / `jm_value_nil` / `jm_value_make_text` |
| 整数范围 | ±268,435,455（29 位）。超范围的 `jm_value_int` 返回 `nil` —— 调用方先做范围检查并报 `JM_NE_PARAM` |
| 文本 | `jm_value_make_text` 新建，引用计数 1，**所有权交给运行时**，native 不要自己释放 |
| 借用文本 | `jm_value_text` 得到的指针只在本次调用期间有效；出参请新建 |
| 返回对象/容器 | v1 不支持。native 只能产出 int/bool/nil/text；容器由运行时构造 |

内存记账：native 里每次分配都算在同一个静态堆上（固件 `JM_HEAP_SIZE=6144`）。一个 native 反复分配而不产生可回收值，会直接导致 `E017 堆内存耗尽`——这是设计约束，不是 bug。

## 6. 错误传播

```c
return jm_native_fail(st, JM_NE_PARAM, "引脚号越界");
```

| 错误码 | 值 | 含义 |
|---|---|---|
| `JM_NE_PARAM` | 30 | 参数取值非法（越界、通道不存在） |
| `JM_NE_TYPE` | 31 | 参数类型不符（要整数给了文本） |
| `JM_NE_HW` | 32 | 硬件操作失败（总线无响应、外设未就绪） |
| `JM_NE_STATE` | 33 | 当前状态不允许（未初始化、已在用、重复启动） |
| `JM_NE_NOMEM` | 34 | 分配失败 |

规则：

1. `fn` 返回 0 = 成功；返回任何非 0 = 失败，**且必须已经 `jm_native_fail`**。
2. 返回非 0 却没报错 → 运行时补一条 `E033 原生函数状态错误`，便于抓漏（不会静默）。
3. 错误是**终止性**的：VM 停止，`jm_run` 返回 -1，`jm_last_error()` 给出 `错误[E0xx] 文案：detail`。
   从 JM13 起语言有 `抛出` / `尝试` / `捕获`，但这些 native 错误**不可被 `捕获` 拦截**：
   `E030` / `E031` / `E033` 与 VM 故障同级，直接终止程序。
4. native 不要自己 `jm_port_write` 报错信息；错误统一走错误码 + detail，由运行时排版。
5. ABI v2 预留 `jm_native_throw`（native 主动抛出可捕获的值）仅作为将来项记录，v1 不实现，
   所以现在 native 没有任何「可恢复错误」的表达能力。
6. detail 是静态字符串（或调用期间有效），运行时不复制。

## 7. 可重入与中断安全

### 7.1 线程模型

- 一个 `JmState` 只允许**一个线程**进入 `jm_run`。VM 不是可重入解释器。
- native 函数在「持有 VM 的那个线程」里同步执行，因此：
  - 可以调用其他 `jm_value_*` / `jm_native_fail`（它们只碰当前状态）；
  - **不得**递归调用 `jm_run`；
  - **不得**跨线程共享同一个 `JmState`。
- native 自身的可重入性由它自己负责：若同一张表被两个 VM 实例共用（主机端口多进程不会，固件里只有一份 `jm_state`），native 里不得有跨实例的 `static` 可变状态；有的话要按实例隔离或加锁。

### 7.2 中断

**v1 明确禁止在中断里调用 native 函数**，理由是三条同时成立：

1. native 可能分配（静态堆没有临界区保护）；
2. native 可能访问外设总线，耗时不可预算；
3. VM 的值栈/帧栈是单线程结构，ISR 里调用会破坏它。

中断里的正确做法（已有内核 API）：

```c
/* ISR 里只做最小动作：投递事件 */
jmk_sem_post_from_isr(&g_evt_sem);
jmk_queue_send_from_isr(&g_log_q, &ev, 0);
```

然后由承载 VM 的任务在 native 里 `jmk_sem_wait` / `jmk_queue_recv` 取事件、转成砾值返回。**ISR → 内核对象 → 任务 → native** 这条链是唯一允许的跨界方式。

`flags` 位是给 ABI v2 预留的：若将来真需要 ISR 直调，会新增 `JM_NATIVE_ISR_SAFE` 与独立的 ISR 入口，且只允许「无分配、无阻塞、无 VM 栈操作」的函数。现在填任何非 0 值都会登记失败。

### 7.3 阻塞

native 可以调 `jmk_*` 阻塞 API（等信号量、收队列），代价是**阻塞承载 VM 的那个任务**。契约上允许，因为固件里 VM 就属于某一个任务（`log`/`main`），没有第二个任务同时在跑同一个 VM。若以后要做「VM 被抢占式调度切片」，这条必须重谈。

## 8. 与打包（H4）的关系

- `砾包.toml` 里 native 依赖写成「表名 + ABI 版本」，例如：

  ```toml
  [native.f103]
  table = "f103_gpio"
  abi = 1
  ```

- 锁文件记录该表的 ABI 版本与来源包；安装时若运行时的 `jm_native_abi_version()` 不等于依赖声明，直接拒绝安装（而不是等到运行期报 `E004`）。
- **不升版本的情形**：只往表里加函数、改实现。**必须升版本的情形**：改 `JmNativeFn` 签名、改值编码、改错误码含义、改参数所有权约定。
- 升版本要同时更新语言卡的 `abi_version`（`spec/langcard.json`），二者不能各走各的。

## 11. 已落地的板级表：`f103_board` / `f103_adc` / `f103_timer`

代码：[f103_native.c](../firmware/stm32f103/f103_native.c)　表头生成物：[f103_native_table.h](../firmware/stm32f103/f103_native_table.h)　登记点：[main.c](../firmware/stm32f103/main.c)（`jm_run` 之前一行，依次登记三张表）

砾侧调用前必须写对应的 `导入 引脚` / `导入 ADC` / `导入 定时器`；名字与参数个数在编译期校验（见 §12）。表项的名字、参数个数与 C 函数名由 `compiler/src/native_spec.rs` 生成，C 侧不再手写。三张表共 10 项（5 + 2 + 3），未超过 ABI v1 的「8 张表 / 64 项」上限。

| 名字 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `引脚写` | `(引脚, 电平)` | 无 | v0 只接受引脚 `13`（PC13）；电平 `0/1`。**PC13 低电平点亮**，所以 `引脚写(13, 0)` 是亮 |
| `引脚读` | `(引脚)` | 整数 | 读 PC13 的输入寄存器值（0/1） |
| `引脚翻转` | `(引脚)` | 无 | 读当前电平再取反 |
| `串口写` | `(文本)` | 无 | 直接写 USART1（115200 8N1），不换行、不加前缀 |
| `等待毫秒` | `(毫秒)` | 无 | 忙等 0–60000 ms；SysTick 中断仍在跑，调度器不参与 |

几点说明：

- 写了 `导入 引脚` 之后，名字拼错与参数个数不符在**编译期**就报 `E115`；没导入就调用报 `E113`，不会等到运行时 `E004`。运行时仍保留 `E004` 与 `E012` 作为兜底。
- 引脚越界报 `E030`；电平不是 0/1 报 `E030`；`串口写` 收到非文本报 `E031`。
- 这些函数**不能进 ISR**（v1 通则）；需要中断驱动的外设，走 `ISR → jmk 对象 → 任务 → native`。
- 示例：[examples/board/点灯.jsh](../examples/board/点灯.jsh)（首行 `导入 引脚`），构建命令：

  ```powershell
  .\tools\build-firmware.ps1 -Example "board\点灯"
  ```

主机侧验证方式：用同名替身表（同 5 个名字、不碰硬件）跑同一份 `app.jmb`，可确认名字绑定与调用顺序，无需上板。编译期检查不依赖硬件：`tools/test-native-import.ps1` 只编不跑。

### 11.1 串口抓取：一条命令

接线：**PA9 → CH340 的 RXD，PA10 → CH340 的 TXD，GND 共地**（只用 TX/RX/GND，不要靠板子给 CH340 供电）。

```powershell
.\tools\capture-serial.ps1                                   # 默认 COM3 / 115200 / 60 秒
.\tools\capture-serial.ps1 -Port COM5 -Seconds 120 -Out .\build\uart\run1.log
```

- 参数：`-Port`（默认 `COM3`）、`-Baud`（默认 `115200`，8N1 固定）、`-Seconds`（默认 60）、`-Out`（默认 `build\uart\uart-<时间戳>.log`）。
- 顺序固定：**脚本先打开端口并开始录制，屏幕上出现「现在可以按复位键」之后**，你再按 RST，启动段不会漏。
- `DTR` / `RTS` 强制关闭，避免部分 USB 转串口把复位脚拉低造成反复重启。
- 落盘是原始字节（UTF-8，保留固件的 `\r\n`），编辑器可直接打开；收 0 字节时退出码 2，并提示检查 TX/RX 是否接反。

上板核对清单（`examples/board/点灯.jsh`）：`[原生] 板级函数表已登记：f103_board, f103_adc, f103_timer` → 4 轮 `LED 亮/灭`（各 400 ms）→ `翻转后，引脚读 = 0` → `板级示例结束` → `[砾] 程序正常结束` → `[内核] 启动调度器…` → 每 200 ms 一行 `[同步] 收到 seq=N`。

### 11.2 ADC 表：`f103_adc`

代码：`port_adc_init` / `port_adc_read`（[stm32f103_port.c](../firmware/stm32f103/stm32f103_port.c)）＋ `n_adc_init` / `n_adc_read`（[f103_native.c](../firmware/stm32f103/f103_native.c)）。砾侧必须先写 `导入 ADC`。

| 名字 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `ADC初始化` | `()` | 无 | 打开 ADC1 时钟（PCLK2 / 6 = 12 MHz），PA0–PA7 设为模拟输入，上电并执行 RSTCAL + CAL 校准 |
| `ADC读` | `(通道)` | 整数 0–4095 | 对通道 0–7 做一次单次转换；通道号越界报 `E030`，未初始化报 `E033` |

硬件约定：

- 通道 `0..7` 一一对应 **PA0..PA7**，12 位分辨率，参考电压为 VDDA（3.3 V）。换算：整数写法 `电压 ≈ 原始值 × 3300 // 4095`（mV）；小数写法 `原始值 / 4095.0 × 3300`（先除后乘，避免中间量超过 Q12 值域 ±524288）。`ADC读` 返回整数，与小数混算时自动提升为 Q12。
- 输入电压必须在 **0–3.3 V** 之间，且与板子共地；超压会损坏引脚。高阻信号源建议外加运放跟随。
- 采样时间设为 239.5 个 ADC 周期，单次转换约 20 µs 量级；转换是阻塞的，不进 ISR。
- `ADC初始化` 会把 PA0–PA7 全部切成模拟输入，若同工程还要把其中某脚当 GPIO 用，需自行改回。

接线（读 PA0）：

```
信号源 + ── PA0（ADC1_IN0）
信号源 − ── GND（必须共地）
0 V   → 原始值约 0
3.3 V → 原始值约 4095
```

示例：[examples/board/ADC采样.jsh](../examples/board/ADC采样.jsh)，每 500 ms 读一次 PA0，打印原始值与估算电压：

```powershell
.\tools\build-firmware.ps1 -Example "board\ADC采样"
```

### 11.3 定时器表：`f103_timer`

代码：`port_timer_init` / `port_timer_delay_ms` / `port_timer_count`（[stm32f103_port.c](../firmware/stm32f103/stm32f103_port.c)）＋ `n_timer_*`（[f103_native.c](../firmware/stm32f103/f103_native.c)）。砾侧必须先写 `导入 定时器`。

| 名字 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `定时器初始化` | `()` | 无 | 启动 TIM2：`PSC = 系统时钟 / 1000 − 1`，`ARR = 0xFFFF`，1 kHz 自由运行 |
| `定时器延时` | `(毫秒)` | 无 | 按 TIM2 计数忙等 0–60000 ms；范围越界报 `E030`，未初始化报 `E033` |
| `定时器计数` | `()` | 整数 0–65535 | 读当前毫秒 tick；16 位，约 65.5 秒回绕 |

时钟与引脚影响：

- TIM2 挂在 APB1，定时器时钟为 72 MHz（PCLK1 36 MHz × 2）；`PSC = 71999` 得到 1 kHz。若 HSE 缺席退回 HSI 8 MHz，`PSC` 会按 `g_sysclk / 1000 − 1` 自动改为 7999，仍是 1 kHz。
- TIM2 只使用计数器，不占用任何 GPIO，也不改 PA0–PA7 的模拟配置；可与 ADC 同时使用。
- `等待毫秒`（`f103_board` 表）走 SysTick 中断；`定时器延时` 走 TIM2 计数。两者互不依赖，`定时器延时` 不依赖 SysTick 中断是否被关掉。
- 16 位计数在 65.536 s 回绕；差值计算用 `uint16_t` 相减，跨回绕仍正确。单次延时上限 60000 ms，避免和回绕周期贴得太近。

## 12. 编译期 `导入` 与单一事实来源

### 12.1 谁负责什么

| 阶段 | 负责方 | 做的事 | 失败表现 |
|---|---|---|---|
| 编译期 | `micc`（`compiler/src/native_spec.rs` + `codegen.rs`） | 校验 `导入 模块` 的模块名、函数名是否存在、是否已导入、参数个数是否落区间 | `E112` / `E113` / `E115`，退出码 1，不产出 `.jmb` |
| 运行期 | `runtime/src/jm_native.c` | 按名字把 `.jmb` 里的全局名绑定到已登记表项，再按 `min_args` / `max_args` 复核后分派 | `E004`（名字未定义）、`E012`（参数个数） |

关键点：**导入不改变字节码**。`.jmb` 里仍然只有名字、没有函数地址、也没有新的导入指令；`导入` 只决定编译器允许哪些名字出现。运行期仍走原来的「名字 → 表项」绑定，所以主机端口、F103 固件和将来的包安装都共用同一套分派路径。

### 12.2 为什么不会出现两份名字表漂移

1. **唯一事实来源**：模块名、表名、函数名、参数个数、C 函数名全部写在 [compiler/src/native_spec.rs](../compiler/src/native_spec.rs)。
2. **C 侧表是生成物**：`micc --emit-native-header` 生成 [f103_native_table.h](../firmware/stm32f103/f103_native_table.h)；`f103_native.c` 的 `F103_TABLE[]` 直接展开 `F103_NATIVE_TABLE_INIT`，不再手写第二份。
3. **构建期比对**：`micc --check-native` 在 `build.ps1` 与 `build-firmware.ps1` 的第 2 步比对入库头文件与规格，不一致直接失败。所以编译期接受的名字/参数个数，和运行期登记的名字/参数个数，来自同一次生成。
4. **文档同源**：语言卡的 `native_modules` 段也从这份规格生成，`micc --check-langcard` 再保证文档没落后。

### 12.3 编译期规则（v0）

- `导入 模块` 只能写在模块顶层；v0 有三个模块：
  - `引脚` → 原生表 `f103_board`（5 项）
  - `ADC` → 原生表 `f103_adc`（2 项）
  - `定时器` → 原生表 `f103_timer`（3 项）
- 模块名不存在 → `E112`，提示当前可用模块。
- 没导入就调用原生名 → `E113`，提示「先写：导入 <模块>」。
- 已导入但参数个数不符 → `E115`；与导入模块里的名字只差一个字（如 `引脚写写`）也按拼错报 `E115`。
- 原生函数只能直接调用：不能当值使用，也不能用 `令` / `函数` / 赋值覆盖同名（`E115`）。
