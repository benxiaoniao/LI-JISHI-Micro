# JM10 完整调试器方案（单步 / 变量查看 / 调用栈 / 条件断点）

> 状态：**M1 / M2 / M3 已落地**（M3 于 2026-11-09 交付：条件断点、命中计数、断点脚本文件）。日期 2026-11-09。
> 上游：[路径图.md](路径图.md) JM10 缺口①；基线设计：[JMB调试表设计.md](JMB调试表设计.md)（已落地，本方案不重复设计）。
> 结论：调试器只做在**主机端口 `jmrun`**；固件默认 0 开销；唯一需要动的是 `.jmb` 调试段的**新增可选符号表**。不改 JMB 版本、不改操作码、不占原生表、不改 ABI。

---

## 0. 一句话边界

```
源码级调试  = 宿主机 jmrun（读 .jmb + DBG1 调试段，驱动暂停/恢复）
板级调试    = SWD + UART 日志（不受本方案影响）
VM 调试对象 = 绿色任务（root + ≤3 子任务）
JMK 任务    = 只覆盖跑 jm_run 的那个 vm；led/log/idle 是纯 C，VM 看不到
```

**不是**在单片机上跑一个 GDB 服务端，也**不是**给每个 JMK 任务各配一个 VM 实例。

## 1. 现状基线（已有 / 缺什么）

### 1.1 已落地（引 `JMB调试表设计.md`，不重复设计）

| 能力 | 现状 | 证据 |
|---|---|---|
| `.jmb` v4 尾部可选调试段 | `DBG1` + `p5.bit0` + 尾索引，可剥离 | 调试表设计 §3 |
| 语句级「指令偏移 → 文件:行」 | varint 增量 + zigzag，可选列号/文件标签 | 同上 §4 |
| 双向查询 | `micc --line-of` / `--lines-of` / `--debug-dump` | 同上 §5 |
| 单断点运行 | `jmrun --break 文件:行`，命中打印源码行 | [jm_main.c](../runtime/port/host/jm_main.c) `resolve_break` / `jm_host_break_hit` |
| 解释器钩子 | 每条指令前调 `jm_host_break_hit(code, ip)` | [jm_vm.c](../runtime/src/jm_vm.c) 主循环 |

**但当前命中后是「整程序结束」而不是「暂停」**：`jm_host_break_hit` 返回非 0 后主循环走 `done:`，把 4 个绿色任务的值栈和任务体全部释放（[jm_vm.c](../runtime/src/jm_vm.c) 2044–2057）。要能继续单步/看变量，必须先把这条出口拆成「暂停、保存现场、可恢复」。

### 1.2 缺的四块与根本约束

| 缺口 | 根因 | 结论 |
|---|---|---|
| 变量查看 | `.jmb` 代码表只有 `nparams/nlocals`，**没有局部变量名**（`code_entry` 的 `[5]/[6]`） | 必须扩调试段加符号表 |
| 调用栈 | 数据**已经够**：`JmFrame{ code_idx, ip, base }` + 代码表名字索引 | 不需要新字段 |
| 单步 | 没有暂停/恢复出口，没有行级推进状态 | 改解释器出口 + 宿主游标 |
| 条件断点 | 只有单断点、无求值面 | 宿主侧子集求值器 |

**关键事实（决定成本）**：codegen 的局部槽是**每个代码对象一张扁平表、槽号从 0 单调递增、不复用**（`compiler/src/codegen.rs` 的 `nlocals += 1`）；方法 `本` 固定 slot 0、参数紧随其后；闭包捕获写回 `stack[base + cslot]`，`cslot ∈ [nparams, nlocals)`。所以 **slot → 名字是每代码对象 1:1**，不需要「ip 区间 → 作用域」那套复杂映射。这是本方案能做到小的前提。

## 2. 调试信息：`DBG1` 追加可选符号表

### 2.1 不改什么

- `dbg_version` 仍为 **1**；不升 JMB v5；`p5.bit0`、尾索引、文件表、代码目录、行记录**布局全不变**。
- 符号表**追加在行记录之后、尾索引之前**，用段头偏移 14 的 `reserved`（u16）改为 `sym_off` 指向它，`0 = 无符号表`。
- 旧读取器不读 `sym_off`，行记录偏移仍有效；新读取器按 `flags.bit2` 判断是否解析。**旧文件、剥离文件零扫描、零 RAM。**

### 2.2 新增字段与布局

段头唯一改动：

| 偏移 | 字段 | 变化 |
|---|---|---|
| 5 | flags | 新增 **bit2 = 有符号表**；bit0/bit1 不变 |
| 14 | reserved → **sym_off** | 0 = 无；否则指向段内符号区 |

符号区（起点 `sym_off`，全部段内偏移）：

```
代码对象目录   ncodes × u16 entry_off      ; 0 = 该对象无符号表
代码块          u8 n
               n × { u8 slot ; u16 name_off }  ; 显式槽号，名字偏移相对 sym_off
字符串池        UTF-8，名字以 0 结尾
```

- **与最初设计的偏差（M1 实施时更正）**：原设计写「`nlocals_n × u16`，顺序即 slot 0..nlocals_n-1」不成立——`alloc_temp` 造的无名临时槽同样递增 `nlocals`，槽号序列里夹着空位。因此改为显式 `{slot, name_off}`，只收录有名字的槽。
- 只在有具名局部的对象写代码块；任一名字偏移/槽号越界，读取端整段禁用（不崩）。
- 名字直接复用源码标识符（中文名字就是 UTF-8，3 B/字），**不另建 id 映射**。
- 体积公式：`2×ncodes + Σ(1 + 3×n) + 名字字节`（`n` = 该对象的具名槽数）。
- **实测（2026-11-08，`micc` release，20 个 `examples/*.jsh`，含调试段）**：符号区 `DBG1.total_len − sym_off`，最大 **289 B**（`数据采集器`，518 B 调试段中 289 B），`闭包` **212 B**、`类` **117 B**；20 个样例中 12 个为 0 B，平均 38.4 B，合计 768 B。**落在 200–400 B 估算区间内**，未超。

### 2.3 编译器侧改动面

- `--strip-debug` 同时丢弃符号表（现成开关）。
- 新增 `micc --locals-of <文件.jmb> <代码序号>` → 逐行 `槽号 名字`，与 `--line-of` 同构，供宿主按需查询（避免把整张符号表载入内存）。
- 代码生成阶段收集 `(slot, name)`：scope 表已经持有 `String → slot`，只需在写调试段时反向导出；**不动 AST、不动字节码、不动操作码**。

## 3. VM 运行时内省接口

新增 `runtime/include/jm_debug.h` + `runtime/src/jm_debug.c`，**全部只读、全部 `#ifdef JM_DEBUG_HOOKS`**（固件默认不编译）。

```c
/* 任务视图 */
int      jm_dbg_task_count(void);                 /* 1..4（root 恒为 0） */
int      jm_dbg_current_task(void);
int      jm_dbg_task_state(int task);             /* FREE/READY/RUNNING/SLEEPING/DEAD */

/* 调用栈：由内到外，返回实际填充帧数 */
typedef struct { uint8_t code; uint16_t ip; uint16_t base; uint8_t nlocals; } JmDbgFrame;
int      jm_dbg_frames(int task, JmDbgFrame *out, int max);

/* 值读取：borrowed，不 retain；调用方不得跨暂停点持有 */
int      jm_dbg_local(int task, int frame, uint8_t slot, JmValue *out);
int      jm_dbg_global(const char *name, JmValue *out);   /* 走现成 name 表 + globals[] */
int      jm_dbg_code_name(uint8_t code, const char **out);/* 代码表 name_idx → 名字 */

/* 值→文本：复用现成 jm_repr()，宿主只提供 sink */
int      jm_dbg_value_text(JmValue v, char *buf, size_t cap);
```

- `jm_dbg_global` 不需要符号表：全局名本来就在 `.jmb` 名字表里，`globals[name_idx]` 直接可读（`OP_LOAD_GLOBAL` 已是这条路径）。
- `jm_dbg_local` 按 `frames[frame].base + slot` 读值栈，**不需要新结构**。
- 全部接口在 `jm_state` 单例上工作（现状 `JmState jm_state;`），不做多实例。

## 4. 解释器钩子与「暂停 / 恢复」

### 4.1 钩子

把现有「每指令前一次调用」保留，签名扩展为带帧深：

```c
/* 返回 0=继续，1=暂停（调用方已保存现场），-1=致命 */
int jm_host_dbg_tick(uint8_t code, uint16_t ip, uint8_t fp);
```

- 编译开关 `JM_DEBUG_HOOKS`：未定义时该调用整体消失（保持固件 0 B）。
- 匹配逻辑**不进 VM**：`jm_host_dbg_tick` 在宿主 `jm_dbg.c` 里做「code 过滤 → ip 二分 → 条件求值」。

### 4.2 暂停/恢复出口

```c
/* 主循环里：命中断点时 */
f->ip = ip;                                  /* 提交现场，保证可恢复 */
st->tasks[st->current].state = JM_TASK_READY;
jm_green_swap_out(st);                       /* 保存 sp/fp/tp 到任务槽 */
jm_dbg_mark_paused(st->current);             /* 暂停状态放在 jm_debug.c 静态变量 */
return 1;                                    /* 新增第三种返回：0=正常结束，1=暂停，-1=故障 */

/* 不执行 done: 清理；所有任务值栈/帧栈原地保留 */
```

- **不新增 `JmState` 字段**（原稿的 `st->dbg.paused` 取消）：暂停状态与暂停任务号放 `jm_debug.c` 的 `static`，关开关时既不加 RAM 也不加代码。
- `jm_run` 原样返回 1 给 `jmrun`；`jm_dbg_resume()` 重新进入 `jm_execute`，先把 `st->current` 挪到暂停任务的前一个槽位，`jm_green_pick` 便会第一时间选回它。
- **兼容性**：宿主回归脚本只看 `rc==0`；暂停只发生在带 `--dbg` 的调试运行，普通 `jmrun` 与旧 `--break` 行为不变。
- 每指令开销：未命中时 1 次 code 比较（绝大多数指令）；命中 code 时一次线性比对（M1 单断点）。只在宿主，**不计入 MCU**。

## 5. 单步与断点的语义

### 5.1 四种运行控制

| 命令 | 行为 | 停止点 |
|---|---|---|
| 继续 | 跑到下一个断点或程序结束 | 断点 / 结束 |
| 单步指令 | **被选中任务**再执行 1 条指令 | 该任务下一条指令前 |
| 单步行 | 该任务第一次「行号变化」处停（同一行的多条指令不逐条停） | 新行首条指令 |
| 步过 | 行级 + 帧深不超过起始帧深 | 本帧下一行；进入被调函数后不再停 |

行级判定用宿主游标：**M2 改为一次 `micc --line-table` 预取全量行表**（`{code, off, file, line}` 四列），宿主按 `(code, off)` 二分查最后一次 ≤ 当前 ip 的记录；`fp` 从 `jm_dbg_frames` 读，不需新增 VM 状态。

> **进度**：M1 交付 `继续` / `单步指令`（`s` 是**指令级**，同一源码行有多条指令会连停数次）；**M2 交付 `单步行`（`n`）/ `步过`（`o`）**，行身份 = `(file_id, line)`，行变化才停，步过额外要求帧深不超过起始帧深；**M3 交付条件断点 / 命中计数 / 断点脚本文件**（见 §7.3）。
>
> 命令与开关：REPL `n` / `下一行`、`o` / `步过`、`b <文件>:<行> [if 名字 比较符 字面量] [#N|%N]`、`bl` / `断点列表`；`jmrun --dbg --break <规格> ...`（与 `--break-file` 合计 ≤8，第 9 个退出码 2）、`--break-file <文件>` 与 `--task N`（后两者必须与 `--dbg` 同用，否则退出码 2）。`--line-table` 是 M2 新增的编译器命令。

### 5.2 绿色任务 vs JMK 任务

| 维度 | 绿色任务（root + ≤3 子任务） | JMK 任务（idle/led/log/churn） |
|---|---|---|
| 是否 VM 可见 | 是，`tasks[0..ntask-1]` | **否**，是纯 C，VM 内省拿不到 |
| 断点语义 | 默认「任意绿色任务命中即停」；可加 `task=N` 过滤 | 无 VM 断点；只能用 SWD 硬断点 |
| 单步语义 | 只推进**被选中任务**；其余绿色任务冻结（VM 停在循环里本来就不会调度） | 不适用 |
| 被选中任务让出/延时/退出 | 该步**视为完成**，停在调度点并报告「任务 N 挂起/退出」，不自动跳到别的任务 | 不适用 |
| 「vm」本身 | 只是承载 `jm_run` 的那个 JMK 任务；调试器暂停 = 该 C 任务暂停 | 其余 JMK 任务仍受 SysTick 抢占（板上才有意义；主机无 JMK） |
| 板上可用性 | 不支持交互式；仍用 SWD + UART 日志 | 同左 |

**若将来要「每个 JMK 任务各跑一个 VM」**：先得把 `JmState jm_state` 从全局单例改成每任务实例，并解决 `jmk` 与 VM 的栈/优先级耦合——这是独立条目，**不在 JM10**。

### 5.3 条件断点（子集）

- 结构：`{ code, ip, task_filter(-1=任意), hit_count, cond }`。
- 条件语法只支持：`名字 比较符 字面量`，比较符 `== != < <= > >=`；`名字` = 当前帧局部名（经符号表）或全局名；字面量 = 整数 / 文本 / `真|假`。
- 求值顺序：命中 ip → `hit_count` 递增 → `hit_count` 满足 `== N / > N / % N == 0` → 求值条件 → 成立才停，不成立自动继续。
- **明确不做**：任意表达式、函数调用、赋值副作用。要更强条件，用「命中计数 + 手动继续」组合，或回源码加一个专门的 `打印` 调试点。

**M3 落地后的精确语义（与实现一致）**：

| 维度 | 定义 |
|---|---|
| 规格 | `文件:行 [if 名字 比较符 字面量] [#N|%N]`，三段可任意组合；顺序固定为位置 → 条件 → 计数 |
| 求值位置 | **宿主 `jm_host_dbg_tick` 命中该 ip 时**求值一次；VM 只调钩子，条件解析与比较全在 `jm_main.c`，不进 VM、不进 `JmState` |
| 局部名解析 | 先按**当前代码对象**的符号表（`micc --locals-of`）找槽号；找不到按全局名（`jm_dbg_global`）。读的是**当前执行帧**（`jm_dbg_local_current` 用 `st->fp`），不是暂停后保存的 `tasks[].fp` |
| 计数起点 | 命中计数**从 0 开始，每次命中先 +1**，因此 `#2` 是「第 2 次命中」，`%2` 是「第 2、4、6…次命中」 |
| 求值失败 | 未知名 / 槽未赋值 / 类型不匹配（文本与整数比大小、文本与整数比相等）→ **只 `警告` 一次，按条件不成立继续**，不中断程序、不删除断点 |
| 比较规则 | 整数：六种比较符；文本：按 `jm_repr(quoted=0)` 的原样字节比较，只允许 `== !=`；布尔：只允许 `== !=` |
| 文本字面量 | `"文本"`（可含空格）或**裸文本**（不含空格、不是整数/`真`/`假`）。裸写是为命令行准备的：PowerShell 5.1 传原生参数会吃掉内嵌双引号 |
| 断点脚本文件 | UTF-8（可带 BOM），一行一条规格；空行与 `//` 开头的行跳过；任一行出错打印 `断点脚本 <path> 第 N 行：<原因>` 并**退出码 2，整份不执行**（不是部分生效） |
| 容量 | `--break` 与 `--break-file` **合计 ≤8**；第 9 个退出码 2 |
| 互斥 | 条件、计数、`--break-file` 都必须与 `--dbg` 同用，否则退出码 2 |

## 6. Flash / RAM 代价

| 位置 | 代价 | 口径 |
|---|---|---|
| 固件（默认） | **0 B**（`JM_DEBUG_HOOKS`/`JM_HOST_DEBUG` 未定义，`jm_debug.c` 编成空单元） | **实测**：`board\OLED文字`，同参数 A/B 链接，含/不含 `jm_debug.c` 两份 ELF 均为 FLASH 45604 B / RAM 17340 B；**M2 与 M3 完成后复测仍 45604 / 17340，相对 M1 / M2 增量均为 0 B**（M2、M3 只改宿主 `jm_main.c`，运行时只新增只读接口） |
| 固件（只开 `JM_DEBUG_HOOKS`、端口未接交互） | 暂停出口 + 弱钩子 + 暂停状态：**+100 B Flash / +8 B RAM** | **实测**：`board\OLED文字`，`-Os`，FLASH 45604→45704，RAM 17340→17348；**M2 / M3 复测仍 45704 / 17348，增量 0 B**。内省接口因无人引用被 `--gc-sections` 丢弃，M3 新增的 `jm_dbg_value_kind/int/bool` 与 `jm_dbg_local_current` 同样被丢弃 |
| 宿主 `jmrun` | 只受 PC 约束 | 增量体积 **未覆盖**（不在默认交付链路，未单独量） |
| `.jmb` 调试段 | 符号区 `2×ncodes + Σ(1+3×n) + 名字` | **实测**：20 个示例最大 289 B、平均 38.4 B（见 §2.2） |
| 发布固件 | 0 B（`--strip-debug` 丢弃整个调试段） | 实测 `build\stm32\app.jmb` 内无 `DBG1` 字样 |
| 调试段体积报告（工具化） | 不占 Flash，只影响 `.jmb` | **实测**：`build-firmware.ps1` 额外产出 `app.debug.jmb`（不剥离），`size-report.ps1` 报「剥离前 4562 B / 剥离后 3983 B / 调试段 579 B（12.7%）」，并把 `jmb_debug` 写入快照与基线对比；示例 `board\OLED文字` |

**不改 RAM 结构**：`JmFrame` 6 B、`JmGreenTask` 36 B、值栈/帧栈/try 栈切片全部不变；暂停只发生在宿主进程内，不占 MCU RAM。

**容量约束**：本方案**新增原生项 0 项**，native 表仍是 7 张 / 29 项（余 1 张 / 35 项），不占任何余量。

### 7.1 M1 实施记录（2026-11-08）

## 8. 风险与已知取舍

1. **暂停/恢复打破「一次跑完」假设**：`jm_run` 增加返回码 1；所有调用方必须把 1 当「暂停」而不是失败。`jm_main.c` 与测试脚本要同步（已在 M1 列入）。
2. **调试段与字节码不同步**：源码改了未重编时，行记录/符号表可能越界。读取端做上界校验，任一越界就整段禁用并报「没有可用调试信息」，**不崩**。
3. **符号表只到砾函数级**：native 内部、C 栈帧、JMK 任务不可见；这是边界，不是缺陷。
4. **局部槽不复用**（当前 codegen 事实）：如果未来改成块级复用槽位，slot→名字就不再 1:1，需要升级为「ip 区间 + 作用域」表，本方案要随之改。**M1 已用 `FnState::symbols()` 内的 `debug_assert` 锁「一槽一名」**（仓库无 Rust 测试基建，故不是独立测试）。
5. **调试信息体积**：符号表不计入 `.jmb` 体积上限（沿用调试表设计 §12 第 9 条），但体积报告要同时报「剥离前/剥离后」两个数。
6. **板上不承诺**：本方案不提供板上交互式调试，避免把 20 KB RAM 和 64 KB Flash 花在调试通道上。
